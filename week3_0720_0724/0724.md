# Linux

## 유저 관리

### 1) 사용자 계정 관리 파일

- `/etc/passwd`
    - 사용자 계정 정보가 저장된 기본 파일
    - 초창기 유닉스에서는 비밀번호도 이 파일에 저장했으나 해킹 위험이 증가하면서 암호는 `/etc/shadow` 파일에 별도로 저장
    - root 계정으로 수정이 가능한데 직접 수정보다는 명령어로 수정하는 것을 권장
    - 구조
        - `etakyung:x:1000:1000:etakyung:/home/etakyung:/bin/bash`
        - 맨 앞은 계정
        - 두 번째 항목 x는 이전에 비밀번호인데 지금은 x
        - 세 번째 항목 1000은 UID로 사용자를 구분하기 위한 번호로 0~999, 65534 는 시스템이 사용하고 1000부터 할당
        - 네 번째 항목 1000은 GID로 그룹을 구분하기 위한 번호
        - 다섯 번째 항목 Ubuntu 는 설명
        - 여섯 번째 항목 /home/etakyung 은 홈 디렉토리
        - 일곱 번째 항목 /bin/bash 는 로그인할 때 사용하는 쉘

    - 그룹에 대한 정보는 /etc/group 파일에 저장되어 있음

- `/etc/shadow`
    - 비밀번호 관리를 위한 파일
    - 해시를 이용해서 저장
    - 이전에는 SHA-512 방식을 사용했는데 지금은 yescrypt 방식으로 보안성을 강화함
    - 단방향 해시: 원래 데이터와 비교해서 일치 여부는 판단할 수 있지만 원래 데이터를 복원할 수 없는 방식

    - 내용
        - `etakyung:$6$zC7WcjBbGfDwmkV.$h/sILnR6M9tEapTcTJc0gMzEYdsttz.fPiQ9kk3mIswUgHKyODe2Aq4vv/mGscVUEUhKf87UDP3eYYBTsMwkU/:20654:0:99999:7:::`
        - 첫 번째 항목은 로그인 아이디
        - 두 번째 항목은 비밀번호
        - 세 번째 항목은 20654는 최종 변경일(1970년 1월 1일로부터 지나온 시간)
        - 네 번째 항목 0은 암호를 사용할 수 있는 최소 기간으로 3이면 암호 변경 후 최소한 3일은 그 암호를 사용해야 한다.
        - 다섯 번째 항목 9999는 암호를 사용할 수 있는 최대 기간으로 이 기간이 지나기 전에 암호를 변경해야 한다.
        - 여섯 번째 항목 7은 만료가 되기 7일 전부터 경고 메시지를 보냄
        - 일곱 번째 항목은 만료가 되고 며칠 동안 로그인 가능하도록 할 지 설정
        - 여덟 번째 항목은 만료가 이 날짜가 지나면 로그인을 할 수 없도록 하는데 1970년 1월 1일을 기준으로 한 날 수로 표시
        - 아홉 번째 항목은 미래를 위한 값
        - 네 번째 항목부터 여덟 번째 항목까지를 aging 정보라고 한다.

- `/etc/login.defs`
    - 사용자 계정의 설정과 관련된 기본값을 정의한 파일

- `/etc/group`
    - 그룹에 대한 정보
        - `adm:x:4:syslog,etakyung`
    - `adm은` 그룹이름이고 `x`는 그룹 비밀번호이고 `4`는 그룹아이디이고 `syslog` 와 `etakyung` 은 그룹의 멤버
    - 그룹의 비밀번호는 `/etc/gshadow` 파일에 존재한다.

### 2) 계정 관리 명령

- `useradd`
    - 사용자 생성
    - 기본 형식
        - `useradd [옵션] [로그인id]`
    - 옵션
        - `u uid`
        - o: uid 중복 가능
        - g gid
        - G gid: 2차 그룹
        - d 디렉토리이름: 홈 디렉토리 이름 변경
        - s 셸: 로그인 셸 변경
        - c 설명
        - D: 기본값을 설정하거나 출력
        - e 유효기간: EXPIRE 항목을 설정(YYYY-MM-DD)
        - f 비활성일수
        - k 디렉토리: 계정 생성 시 복사할 초기 파일이나 디렉토리를 설정해 놓은 디렉토리를 설정

    - 옵션 없이 계정 생성
        - `sudo useradd user2`
        - 비밀번호를 설정: `sudo passwd user2`

    - 옵션을 이용해서 생성
        - `sudo useradd -d /home/user3 -u 2000 -g 1000 -G 3 user3`
    - 잘 생성되었나 확인: `cat /etc/passwd`
        - `user2:x:1001:1001::/home/user2:/bin/sh`
        - `user3:x:2000:1000::/home/user3:/bin/sh`

- `adduser`
    - 사용자 계정 생성 명령
    - 기본 형식
        - `adduser [옵션] 로그인id`
    - 옵션
        - `--uid UID`: UID를 지정
        - `--gid GID`: 기본 그룹의 GID를 지정
        - `--home DIR`: 홈 디렉토리를 지정
        - `--shell 셸`: 기본 셸을 지정
        - `--gecos 설명`: 사용자의 이름 등 부가적인 설명을 지정
    - 암호를 계정 생성할 때 입력하라고 함

- `usermod`
    - 계정 정보 수정
    - 기본 형식
        - `usermod [옵션] [로그인id]`
    - 옵션
        - `u uid`: UID를 수정
        - `o`: UID의 중복을 허용
        - `g gid`: 기본 그룹을 수정
        - `G gid`: 2차 그룹을 수정
        - `d 디렉토리이름`: 홈 디렉토리를 수정
        - `s 쉘`: 기본 셸을 수정
        - `c 설명`: 부가적인 설명을 수정
        - `f inactive`: 계정 비활성화(INACTIVE) 날짜를 수정
        - `e expire`: 계정 만료(EXPIRE) 날짜를 수정
        - `l`: 계정 이름을 변경

- `패스워드 에이징`
    - useradd, usermod, passwd, chage 명령으로 설정
    - chage 명령이 패스워드 에이징을 관리하는 별도의 명령

    | 항목       | useradd, usermod, passwd 명령                                | chage 명령   |
    | -------- | ---------------------------------------------------------- | ---------- |
    | MIN      | `passwd -n 날수`                                             | `chage -m` |
    | MAX      | `passwd -x 날수`                                             | `chage -M` |
    | WARNING  | `passwd -w 날수`                                             | `chage -W` |
    | INACTIVE | `useradd -f 날수`<br>`usermod -f 날수`                         | `chage -U` |
    | EXPIRE   | `useradd -e 날짜(YYYY-MM-DD)`<br>`usermod -e 날짜(YYYY-MM-DD)` | `chage -E` |


    - passwd 명령으로 기본값을 설정
        - `sudo passwd -n 3 -x 100 -w 5 user3`

### 4) 사용자 정보 관리

- UID 와 EUID
  - UID 는 RUID 라고도 하며 EUID 는 유효 사용자 ID
  - RUID 는 사용자가 로그인 할 때 사용하는 ID 이고 EUID 는 현재 명령을 수행하는 주체의 UID
  - UID 와 EUID 가 달라지는 경우
    - 실행파일에 setuid가 설정된 경우: 해당 파일을 실행한 프로세스의 UID 는 사용자 계정의 UID 가 아니라 실행 파일 소유자의 UID가 된다.

    - su 명령을 사용해서 다른 계정으로 전환한 경우

- 사용자 확인 명령
  - 로그인 정보 확인: who
  - `w [사용자 계정]`
    - 사용자 정보 이외에 현재 실행 중인 작업에 대한 정보를 같이 알려줌
  - `last`
    - 사용자 계정과 로그인한 시간, 로그아웃한 시간, 터미널 번호 그리고 IP 주소를 출력
  - UID와 EUID 확인: `whoami`, `who am i`, `id`

- root 권한 사용
  - 사용하는 방법
    - su 명령을 이용해서 root로 계정을 전환: 보안상 매우 위험
    - 일반 사용자에게 시스템 관리 작업 중 특정 작업만 수행할 수 있는 권한을 주는 방식으로 `sudo` 명령으로 제한적인 권한 부여가 가능

- sudo 권한 설정
  - 일반 사용자가 sudo 명령으로 root 권한을 사용하려면 특정 권한을 부여 받아야 함.
  - 권한은 /etc/usdoers 파일에 설정해야 하는데 이 파일은 root 계정으로만 수정이 가능
  - 텍스트 편집기로 수정해도 되지만 일반적으로 visudo 명령으로 수정하는 것을 권장
  - visudo 명령은 문법에 맞는지 확인하고 저장

  - 현재 설정 내용
    - root ALL=(ALL) ALL
  - 권한 부여
    - 유저 ALL=명령 나열
    - 명령은 절대 경로로 설정해야 하고 여러 개일 때는 쉼표로 구분
      - `user2 ALL=/usr/sbin/useradd, /usr/sbin/usermod`

- sudo 명령 사용
  - 명령 형식: sudo 명령
  - 일반 사용자에게 모든 권한을 부여하는 것은 매우 위험

- 파일 및 디렉토리의 소유자와 소유 그룹 변경
  - chown 명령
  - 형식: `chown [옵션] [사용자 계정] [파일이나 디렉토리 경로]`
  - 사용하는 경우는 인터넷에서 다운로드 한 파일의 소유자를 변경해서 사용
    - 다운로드 파일의 경우는 접근 권한을 우리가 설정하지 않아서 원하는 접근 권한을 가지도록 변경할 때 chmod를 이용하는 방법이 있고 다른 하나는 소유자를 변경해서 사용하기도 한다.

- 실습
  - 디렉토리  생성: `mkdir linux_ex`
  - 생성한 디렉토리로 이동: `cd linux_ex`
  - 디렉토리 생성: `mkdir usermanagement`
  - 생성한 디렉토리로 이동: `cd usermanagement`
  - 파일 복사: `cp /etc/hosts .`

- chgrp: 소유 그룹 변경


### 3) 디스크 사용량 설정

- 개요
  - 리눅스는 여러 사용자가 함께 사용하는 시스템이므로 특정 사용자가 과도하게 디스크를 사용하지 않도록 제한할 필요가 있음
  - 사용자가 사용할 수 있는 디스크 크기를 제한하는 방법이 있고 파일의 개수를 제한하는 방법이 있음
  - 제한을 설정할 때는 `hard limit` 와 `soft limit` 가 있는데 `hard limit` 는 절대로 넘어설 수 없는 최대치를 명시하는 것이고 `soft limit` 는 일정 시간 내에서는 넘을 수 있는 한계치를 설정하는 것
  - 할당된 디스크 쿼터를 초과할 경우 사용자는 파일을 지워서 한계치 아래로 디스크 사용량을 
  - 우분투에서는 `quota` 패키지를 이용

- 쿼터 설정 준비
  - 쿼터 속성 설정: `/etc/fstab`

    | 파티션 | 마운트된 디렉토리 | 파일시스템 | 옵션 | dump | pass |
    |---|---|---|---|---|---|
    | /dev/sdb1 | /mnt | ext4 | defaults,usrquota | 1 | 1 |

  - 쿼터 속성 적용
    - `sudo mount -o remount /mnt`
    - `sudo systemctl daemon-reload`
    - `mount`
  - 데이터베이스를 생성: `sudo quotacheck -ugvm /mnt`
  - 쿼터 사용 활성화: `sudo quotaon -uv /mnt`

- 쿼터 설정
  - `eduquota [옵션] [사용자 계정]`
  - `sudo edquota -u user1`

- 클라우드 서비스 중 메일이나 디스크 관련 서비스에서는 이 기능을 많이 사용한다.

### 1) C Programming

  - 현재 디렉토리를 PATH에 추가하면 `hello.out` 만으로 가능하다.
  - `export PATH=$PATH:/home/etakyung/programming`

### 2) make
- 실제 패키지는 많은 파일로 복잡하게 구성되기 때문에 gcc로 일일이 컴파일해서 하나의 실행 파일로 만드는 것은 매우 번거로운 작업인데 이를 간단하게 해결할 수 있도록 해주는 것이 `make`
- make는 makefile 에 설정된 정보를 읽어서 여러 소스 파일을 컴파일하고 
- 소스로 배포되는 많은 오픈 소스 소프트웨어는 소스 코드와 함께 make
- make 가 있는지 확인해보고 없으면 설치
  - `sudo apt install make`

- 실습
  - one.c 파일 작성
  ```c
  #include <stdio.h>
  extern int two();
  int main() {
    printf("Go to Module Two—-\n");
    two();
    printf("End of Module One.\n");
  }
  ```
  - two.c 파일 작성
  ```c
  #include <stdio.h>
  int two() {
    printf("In Module Two--\n");
    printf("--- This is a Module Two.\n");
    printf("End of Module Two.\n");
  }
  ```
  - makefile 작성: `vim makefile`
  ```makefile
  TARGET=one
  OBJECTS=one.o two.o
  ${TARGET} : ${OBJECTS}
  	gcc -o ${TARGET} ${OBJECTS}

  one.o : one.c
  	gcc -c one.c
  two.o : two.c
  	gcc -c two.c
  ```

const http = require("http")

## 네트워크 관리

### 1) 네트워크 기본 개념

- `TCP/IP` 프로토콜
  - 프로토콜: 통신을 하기 위한 규칙 또는 규약
  - TCP/IP: 인터넷이라는 통신망의 프로토콜

- `MAC Address`
  - `Media Access Control` 의 약자로 MAC 주소는 하드웨어를 위한 주소인데 이더넷 주소, 하드웨어 주소, 물리 주소라고도 불린다.
  - `NIC(Network Interface Card - 네트워크를 사용하기 위한 하드웨어)`에 저장된 주소
  - `MAC Address`는 하드웨어 제조 과정에서 부여되며 원칙적으로는 수정할 수 없지만 운영체제에 따라 수정하는 것이 가능

  - `:` 이나 `-`로 구분되는 여섯 개의 16진수로 구성되는데 총 48bit
  - 00:50:56:3e:3c:fe 의 형태로 작성되는데 앞의 3개는 제조사 번호이고 뒤의 3개는 일련번호

- `IP Address`
  - 인터넷 주소 체계
  - 주소의 종류는 여러가지인데 지금은 `IPv4` 와 `IPv6` 만 사용
  - `IPv4`
    - 32비트 주소 체계로 8비트씩 끊어서 10진수로 표현하며 구분은 .
    - 0~255까지의 숫자 4개로 표현
    - 현재는 주소가 고갈이 돼서 `IPv6` 를 사용
  - `IPv6`
    - 128 비트 주소 체계
    - 16진수 2개씩 묶어서 표현
    - 구분은 `::` 

- `NetMask`
  - IP 주소에서 네트워크 부분을 알려주는 역할을 하는 것
  - 동일한 네트워크를 나타내기 위해서 사용하는 것인데 내부 통신이 가능한 영역을 표현하기 위한 것
  - 표현 방식은 IP처럼 10진수 네자리로 표현하기도 하고 1의 개수를 표현하기도 함

  - 192.168.0.2 255.255.255.0 또는 192.168.0.2/24 형태로 표현한 것
  - 192.168.0.2는 IP주소이고 255.255.255.0
  - 1의 개수가 24개라서 /24 표현하기도 함.
  - 1의 개수 24자리까지가 동일하면 동일한 네트워크로 간주하겠다는 의미
  - 192.168.0 까지가 동일하면 동일한 네트워크로 간주
  - 이 부분이 같은 경우는 통신을 요청하는 경우 외부 라우터로 가지 않고 내부에서 처리

- `Broadcast Address`
  - 동일한 네트워크에 있는 모든 컴퓨터에 메시지를 보낼 때 사용하는 주소
  - 일반적으로 네트워크 대역에서 가장 마지막 주소를 이용
  - 192.168.0.2 255.255.255.0 의 경우는 192.169.0.255

- `호스트 이름`
  - IP 주소 대신에 사용할 수 있는 컴퓨터에 붙이는 이름
  - 도메인은 인터넷에서 사용하는 호스트 이름
  - www.naver.com 이라고 작성을 하는데 naver.com 이 네트워크 부분이고 www.는 호스트 부분

- `DNS(Domain Name System)`
  - 도메인을 해석해서 IP로 변환해주는 시스템
  - 도메인을 입력하면 DNS가 해석해서 IP로 변환해주고 이 IP를 가지고 컴퓨터를 찾아가게 된다.

  - IP를 이용하면 도메인을 이용하는 것보다 속도가 빠름

- `DHCP(Dynamic Host Configuration Protocol)`
  - IP 주소 관리를 자동화하기 위해 사용되는 네트워크 프로토콜
  - 네트워크에 연결되는 모든 장비를 기본적으로 IP주소, 넷마스크, 기본 게이트웨이, DNS Server 주소를 설정해야만 인터넷을 사용할 수 있는데 DHCP 서버를 만들면 장비들은 DHCP 서버에게 할당할 내용을 요청하고 DHCP 서버는 할당 가능한 주소를 찾아서 대여를 해주게 된다.

- `Gateway`
  - 로컬 네트워크에서는 내부 컴퓨터에 대한 정보만 알 수 있기 때문에 외부 네트워크로 나가고자 하면 다른 장비의 도움이 필요
  - 외부 네트워크로 나가기 위해서 거쳐야 하는 장비 (라우터)
  - 인터넷을 할 때는 Gateway를 이용해서 요청을 하게 된다.
  - 인터넷을 하려면 게이트웨이를 설정해 주어야 한다.
  - 보통 게이트웨이는 사용 가능한 네트워크 주소 대역에서 첫 번째 주소를 많이 사용한다.
  - 192.168.0.2/24 이면 192.168.0.1 이 되는 경우가 많고 마지막 주소를 사용하기도 한다.
  - 192.168.0.254 를 사용하기도 한다.

- `포트 번호`
  - 컴퓨터 내부에서 통신이 가능한 애플리케이션을 구분하기 위한 번호
  - 0~65535 까지 가능
  - 0~1023 번은 국제 표준으로 합의해서 사용하고 있는데 할당을 해도 된다.
	- 확인하고자 하면 `cat /etc/services` 에 작성되어 있다.

- 인터넷이 가능하도록 하기 위해서 설정할 주소
  - `IP Address`
  - `Subnet Mask`
  - `Broadcast Address`
  - `Gateway Address`
  - `DNS Address`

### 2) 네트워크 설정

- ip 명령으로 주소 관리
  - 형식
    - `ip [옵션] 객체 [서브 명령]`
  - 옵션
    - `V`: 버전을 출력
    - `s`: 자세한 정보 출력

	- 객체와 서브 명령
  	- `address [add | del | show | help]`: IP 주소 관리
  	- `route [add | del | help]`: 라우팅 테이블 관리
  	- `link [set]`: 네트워크 인터페이스를 활성화 또는 비활성화
	- 전체 장치에 대한 상세 정보 출력: `ip addr show`
	- 하나의 인터페이스에 대한 정보 출력: `ip addr show enp0s1`
	- ip 추가 설정: `sudo ip addr add 192.168.1.20/24 dev enp0s1`
	- 이 명령은 재부팅하면 사라지므로 별도의 설정 파일에 저장을 해야 재부팅 후에도 사용이 가능
	- ip 삭제: `sudo ip addr del 192.168.1.20/24 dev enp0s1`

	- 라우팅 테이블과 게이트웨이 주소 관리: `ip route`
  	- 라우팅: 최적의 경로를 찾아가는 것
  	- 라우팅 테이블: 어떤 경로를 찾아갈 때 어떻게 갈 것인지를 저장해 놓은 테이블
		- 라우팅 테이블에 기록되지 않은 곳은 직접 찾아가는 것이 안되고 이 경우에는 게이트웨이를 통해서 찾아가야 한다.
		- 기본 게이트웨이 설정: `sudo ip route add default via IP주소 dev 인터페이스주소`

- net-tools 패키지
  - 네트워크 명령을 가진 패키지: `sudo apt install net-tools`
  - `ifconfig 명령`
  - 형식: `ifocnfig [인터페이스이름] [옵션] [값]`
  - 옵션
    - `a`: 시스템의 전체 인터페이스에 대한 정보를 출력
    - `up/down`: 활성화 및 비활성화
    - `netmask`: 넷마스크 주소 설정
    - `broadcast`: 브로드캐스트 설정

- DNS 설정
  - 리눅스는 DNS 정보를 `/etc/resolv.conf` 파일에 저장
  - nameserver 자리에 127.0.0.53 이 저장되어 있는데 이 주소는 실제 DNS의 주소가 아니고 로컬 스터브 주소를 가리키는 심볼릭 링크
  - DNS 정보 확인: `resolvectl status`
  - nmcli 명령으로 설정: `nmcli con mod 커넥션이름 ipv4.dns DNS 주소`
  - DNS 서버에 질의를 해서 도메인에 해당하는 IP 확인하는 명령: `nslookup`

- `netplan`
  - 우분투에서 네트워크 구성을 관리하는 도구
  - netplan 설정 파일은 YAML 형식으로 작성되며 `/etc/netplan/` 디렉토리에 존재하면 되고 파일의 이름은 의미가 없음
  - 파일을 수정하고 적용할 때는 `sudo netplan apply` 또는 재부팅
  - 설정 파일들은 권한을 변경하는 경우가 있음
    - `sudo chmod 600`
