# Public Cloud - AWS

## 1. AWS

### 개요

- Amazon에서 제공하는 퍼블릭 클라우드 서비스
- 시스템 운영에 필요한 다양한 서비스를 제공
- 다른 퍼블릭 클라우드에 비해 서비스 조합이 쉽고, 매년 서비스가 강화됨
  - AWS와 외부 시스템 또는 네트워크를 연동하는 사례가 늘고 있음
- 종량제: 사용한 만큼 지불
- 웹 브라우저에서 대부분의 설정을 할 수 있어 사용이 쉬움
- 서울에 한국 전담팀 상담 창구가 마련되어 있음
  - AWS 도입을 지원하는 APN(Amazon Partner Network) 기업이 있음
  - AWS가 공식 인증하는 최상위 프리미어 컨설팅 파트너는 국내에 3개사(Megazone Cloud, 베스핀글로벌, GS네오텍)
- 보안 기준 준수
  - 한국은 ISMS(한국 정보보호 관리체계) 인증을 취득하여 기준을 준수하고 있음
- 글로벌 확장이 쉬움
  - 많은 데이터 센터를 보유
  - 한국 서울에도 3개의 AZ(가용 영역)를 보유
- 165개 이상의 서비스 제공
  - 일반적으로 알려진 인프라 대부분을 제공

### 제공하는 서비스

목적에 따라 서버 관리, 분석, 가상 데스크톱, 감시 도구, 로봇 개발, 머신러닝, 인공지능, 블록체인, 인공위성 관련 서비스 등을 제공합니다.

#### 서버 관련 서비스

- **EC2**: 컴퓨팅 자원
- **Elastic IP**: 고정 IP
- **VPC (Virtual Private Cloud)**: 프라이빗 네트워크
- **Route 53**: 도메인 연결
- **Certificate Manager**: HTTPS 인증서 발급
- **Batch**: 일괄 처리
- **API Gateway**: 여러 마이크로서비스에 접근하는 단일 통로 제공
- **CloudFront**: CDN(Content Delivery Network) 서비스
- **Transit Gateway**: VPC 연결
- **Elastic Load Balancer (ELB)**: L4/L7 로드 밸런서
- **ECR**: 이미지 레지스트리
- **ECS**: 클러스터 관리 서비스
- **EKS**: 쿠버네티스 서비스
- **Lambda**: 서버리스 서비스

#### 스토리지 서비스

- **S3**: 오브젝트 스토리지. 파일 서버나 정적 웹 호스팅으로 사용 가능하며 파일 크기는 최대 5TB
- **EBS (Elastic Block Store)**: EC2에서 사용하는 스토리지
- **S3 Glacier**: 파일을 압축해 장기간 보존하는 서비스

#### 데이터베이스 서비스

- **RDS**: 관계형 데이터베이스
- **DynamoDB**: NoSQL 데이터베이스
- **DocumentDB**: MongoDB 호환 도큐먼트 데이터베이스
- **ElastiCache**: 인메모리 캐시 시스템

#### 데이터 집계 및 분석 서비스

- **Redshift**: 대용량 데이터 집계 서비스
- **Athena**: S3에 저장된 데이터 집계 서비스
- **Elasticsearch Service**: 로그, 모니터링, 보안 등의 분석 서비스

#### 애플리케이션 연계

- **SQS (Simple Queue Service)**: 애플리케이션 사이를 연동하는 대기열 서비스
- **SNS (Simple Notification Service)**: 애플리케이션 사이에 알림을 전송하는 서비스

#### 머신러닝

- **SageMaker**: Jupyter Notebook을 제공하며 머신러닝 모델을 구축, 학습, 배포할 수 있는 서비스
- **Bedrock**: 개발자가 대형 언어 모델(LLM)을 포함한 생성형 AI 모델을 API 호출로 사용할 수 있게 해주는 완전 관리형 서비스
  - 사용 가능한 모델
    - Anthropic (Claude)
    - Meta의 Llama
    - Mistral AI
    - Amazon Titan
    - Stability AI: 고품질 이미지 생성에 사용

#### 개발 도구

- **Cloud9**
  - 웹 브라우저에서 조작할 수 있는 통합 개발 도구
  - 다양한 언어를 지원하며 컴퓨터에 개발 도구를 설치하지 않고 시스템 개발 가능
- **CodeBuild**
- **CodeCommit**
- **CodeDeploy**
- **CodeStar**: 빌드부터 배포까지 묶어서 제공하는 서비스
- **CloudFormation**: 인프라를 텍스트 파일로 정의하고 자동 생성·관리하는 IaC 서비스. Ansible이나 Terraform과 유사한 역할
- **CLI**

#### IoT

- **IoT Core**: IoT 디바이스를 클라우드에 연결하는 기본 서비스
- **FreeRTOS**: 마이크로컨트롤러를 위한 실시간 운영체제
- **IoT Things Graph**: 디바이스와 웹 서비스를 상호 연결하는 서비스

#### 가상 데스크톱 서비스

- **WorkSpaces**

#### 비용 관련 서비스

- **Cost Explorer**: 비용 탐색기
- **Budgets**: 예산 관리
- **Cost and Usage Report**: 상세한 비용 내역이 담긴 원시 데이터
- **Compute Optimizer**: AI 기반 자원 낭비 진단 및 최적화 안내 서비스
- **Trusted Advisor**: 비용뿐 아니라 보안, 성능까지 진단하는 서비스

### 사용 방법

- **관리 콘솔**: 웹 브라우저의 GUI로 AWS를 조작
- **Managed Service**: AWS가 관리하는 서비스
  - 백업과 업데이트가 자동으로 이루어져 사용자가 서비스에 집중할 수 있음
  - EC2는 관리형 서비스가 아니지만 RDS는 관리형 서비스

### 용어

#### Region

AWS 서비스가 위치하는 물리적 지역입니다. 각 리전에는 여러 가용 영역(데이터 센터)이 있을 수 있습니다. 가까운 리전에서 접속하면 속도를 높일 수 있고, 한 리전에 장애가 발생해도 다른 리전에서 서비스를 지속할 수 있습니다.

#### AZ (Availability Zone, 가용 영역)

- 데이터 센터와 유사한 개념
- 같은 지역이나 도시 안에서도 각 가용 영역은 물리적으로 분리되어 있음
- 가용 영역에 따라 같은 서비스라도 비용이 다를 수 있음
- ELB는 같은 리전 안의 여러 가용 영역에 걸쳐 트래픽을 분산할 수 있음

#### Edge Location

- AWS CDN 서비스인 CloudFront를 위한 캐시 서버
- CDN(Content Delivery Network)은 전 세계 캐시 서버에 콘텐츠를 복제해 사용자가 빠르게 받을 수 있도록 하는 서비스
- CDN은 인터넷 트래픽을 효과적으로 처리할 수 있는 지역에 POP(Point of Presence)를 구축함
- CDN 서비스와 사용자가 만나는 지점을 Edge라고 부름
- AWS에서는 CloudFront와 Route 53에서 제공

### AWS 작업 도구

- **관리 콘솔**: 웹 브라우저에서 접속해 작업
- **AWS CLI**: 로컬에 설치한 뒤 명령어로 서비스를 사용. 빠르게 서비스를 조작할 때 이용

## 2. EC2

### 개요

- 컴퓨팅 용량을 제공하는 서비스
- 관리형 서비스가 아님
  - 서버와 네트워크 운영은 AWS가 담당하고, 그 이외의 작업은 사용자가 담당
- 클릭 몇 번으로 서버를 생성할 수 있음
- 장점
  - 바로 사용 가능
  - 다양한 선택지
  - 생성과 삭제가 편리
- 단점
  - 서버 1대로 구성되어 변화가 크지 않은 시스템에서는 AWS의 장점을 살리기 어려움

### 주요 구성

- **인스턴스**: AWS 클라우드에 만들어지는 가상 서버. AMI로 같은 구성의 서버를 생성할 수 있음
- **AMI**: 가상 이미지. 인스턴스를 생성하는 기준
- **Key Pair**: 인스턴스 접속 시 인증에 사용하는 키
- **EBS**: AWS 클라우드 스토리지. 인스턴스 스토리지로 사용
- **보안 그룹**: 가상 방화벽. 하나 이상의 인스턴스 트래픽을 제한
- **Elastic IP**: 고정(정적) IPv4 주소

### 요금 체계

- **인스턴스 사용량**: 가동 시간 × 단가. 정지 중에는 과금되지 않음
- **EBS 요금**: 보유 용량 × 단가
  - 저장한 데이터 용량이 아니라 할당한 용량 기준
  - 인스턴스가 정지되어도 과금
- **통신 요금**
  - 아웃바운드(인터넷으로 나가는 통신)만 과금
  - 리전마다 단가가 다름
- **기타 옵션**: Elastic IP 서비스 사용 시 요금이 과금될 수 있음

### 함께 사용하는 AWS 서비스

- Amazon S3
- Amazon RDS
- Amazon CloudWatch: 모니터링 및 관리 서비스
- Amazon Route 53
- Amazon VPC

### 사용 절차

1. 관리 콘솔에서 EC2 대시보드를 열고 인스턴스를 생성합니다.
2. 인스턴스가 생성되면 SSH로 접속해 사용합니다. 웹 브라우저나 로컬 머신에서 접속할 수 있습니다.

### 기본 리전 설정

설정 아이콘을 눌러 **현지화 및 기본 리전 편집**에서 설정합니다.

### 인스턴스 생성

#### 설정 항목

- **이름**: 인스턴스를 구별하기 위한 이름. 계정 내에서만 유일하면 됨
- **AMI 이미지**: 운영체제 이미지
  - Amazon Linux
  - CentOS
  - Red Hat Enterprise Linux
  - Debian
  - SUSE Linux
  - MS Windows
  - Mac OS
  - Tomcat, Nginx, WordPress 등이 설치된 이미지
- **인스턴스 유형**: CPU와 메모리 크기
  - 범용: M으로 시작
  - 컴퓨팅 최적화: C로 시작
  - GPU 인스턴스: G로 시작
  - 메모리 최적화: M2와 CR1으로 시작
  - 스토리지 최적화: H와 I로 시작
  - Micro 인스턴스: 저렴한 유형으로 프리 티어 계정에서 무료 사용 가능
- **키 페어**: 새로 만들거나 기존 키를 사용. 외부 접속에 필요
  - 인증에 사용하는 공개 키와 비밀 키 한 쌍
  - SSH 접속 시 파일 내용을 비밀 키로 사용
  - 다른 리전에서는 사용할 수 없지만 같은 리전 안에서는 공통으로 사용 가능
- **네트워크(보안 그룹) 설정**
  - 기본적으로 아웃바운드 트래픽은 허용
  - SSH, HTTP, HTTPS 외부 접속을 허용하도록 새로 만들거나 기존 보안 그룹을 재사용 가능
- **스토리지 설정**
  - 기본적으로 EBS 사용
  - EBS는 바이트 블록 단위로 저장하는 스토리지
  - HDD와 SSD 중 선택 가능

### 인스턴스 연결

- **관리 콘솔에서 연결**: 연결 버튼을 누르고 화면에서 브라우저 기반 탭을 선택
- **외부에서 연결**:

```bash
ssh -i pem파일경로 계정@publicIP
```

계정은 기본적으로 운영체제 이름으로 생성됩니다.

### Elastic IP

- EC2에서 기본 제공하는 Public IP는 재시작하면 변경됨
- Elastic IP는 고정 IP 서비스
- 인스턴스가 아니라 AWS 계정에 연결됨
- 여러 인스턴스와 연결 가능
- 계정당 기본 1개는 무료이며 추가 사용 시 요금이 과금됨
- 인스턴스와 연결하려면 Elastic IP를 선택한 후 상단의 **주소 연결**을 클릭하고 인스턴스를 선택

### 키 페어 없이 계정과 비밀번호로 SSH 접속

SSH 접속 때마다 PEM 파일을 사용하는 것이 번거로운 경우 설정합니다. 계정을 새로 만들거나 기존 계정을 수정해 사용할 수 있습니다. `/etc/sudoers`와 `/etc/ssh/sshd_config` 파일을 수정합니다.

#### 사용자 생성

```bash
sudo adduser 계정
```

#### 사용자 권한 변경

```bash
sudo chmod u+w /etc/sudoers
sudo vi /etc/sudoers
```

`sudoers` 파일에 다음 내용을 추가합니다.

```text
계정명=(ALL:ALL) ALL
```

#### SSH 접속 방법 수정

```bash
sudo vi /etc/ssh/sshd_config
```

다음 설정을 추가하거나 수정합니다.

```text
PasswordAuthentication yes
KbdInteractiveAuthentication yes
```

SSH를 재시작합니다.

```bash
sudo service ssh restart
```

### 보안 그룹

- 보안 그룹은 인스턴스 앞에서 트래픽을 제어하는 가상 방화벽
- Network ACL(Access Control List)은 서브넷 앞에서 트래픽을 제어
  - 비유하면 Network ACL은 앞문, 보안 그룹은 중문 역할
- Amazon VPC에서는 인스턴스당 보안 그룹을 최대 5개까지 설정할 수 있고 VPC에는 최대 2,500개까지 설정 가능
- 같은 서브넷 안의 인스턴스에도 서로 다른 보안 그룹을 적용할 수 있음
- 인바운드 규칙에서 허용할 트래픽을 설정
- 보안 그룹 설정 시 허용할 포트와 IP 범위를 지정
- 자주 사용하는 포트는 이름으로 선택 가능
- 모든 IP를 허용하려면 Anywhere IPv4 또는 Anywhere IPv6를 선택

### Load Balancing

#### ELB

AWS가 제공하는 로드 밸런서입니다.

#### ELB 종류

- **ALB**
  - L7 로드 밸런서
  - 요청 내용을 확인하므로 대상의 URL 디렉터리 단위로 분배 가능
  - 인스턴스와 로드 밸런서 사이의 암호화 가능
  - 지원 프로토콜: HTTP, HTTPS
- **NLB**
  - OSI 모형의 전송 계층에서 동작하는 L4 로드 밸런서
  - 패킷만 확인할 수 있으므로 분배 대상의 IP 주소를 설정
  - 지원 프로토콜: TCP, TLS
- **GLB**
  - AWS 환경으로 들어오고 나가는 네트워크 트래픽을 NGFW(차세대 방화벽), 침입 탐지·방지 시스템, 심층 패킷 검사 시스템 같은 서드파티 가상 네트워크 장비로 라우팅하고 관리하는 부하 분산 서비스
  - ALB와 NLB는 사용자 요청을 애플리케이션 서버로 분산하는 데 특화되어 있음
  - 기업이 Palo Alto, Check Point, Fortinet 같은 전문 방화벽 장비를 AWS에 도입할 때 발생할 수 있는 문제
    - 복잡한 라우팅 구조: 트래픽이 반드시 방화벽을 거치도록 라우팅 테이블을 복잡하게 설정해야 함
    - 고가용성(HA)의 한계: 방화벽 장비가 중단되면 네트워크 전체가 마비되거나 복구 스크립트가 필요함
    - 확장 어려움: 트래픽이 몰릴 때 방화벽 장비 수를 자동 조정하기 까다로움
  - GLB는 게이트웨이 역할을 하면서 방화벽 장비에 부하를 분산하고, 장애가 나면 정상 장비로 트래픽을 돌려줌
- **CLB**
  - 예전에 지원하던 로드 밸런서
  - 지원 프로토콜이 많다는 장점이 있음
  - 새로 구축하는 시스템에는 사용하지 않는 것을 권장
  - 지원 프로토콜: TCP, SSL/TLS, HTTP, HTTPS

#### Target Group

로드 밸런서가 받은 트래픽을 최종적으로 보낼 대상을 지정하는 그룹입니다. 트래픽을 처리할 실제 서버나 자원을 모아 관리하며, 로드 밸런서를 구성할 때 함께 만듭니다.

**역할**

- 트래픽 라우팅 목적지 지정
- Health Check
- 유연한 구성 관리: 서버를 교체하거나 추가할 때 로드 밸런서 대신 Target Group을 수정

**등록할 수 있는 대상**

- 인스턴스 기반: EC2 인스턴스를 직접 지정
- IP 주소 기반: AWS VPC 안의 자원뿐 아니라 Direct Connect나 VPN으로 연결된 사내 서버 IP도 지정 가능
- Lambda 함수 기반
- ALB

#### ELB 요금

시간당 사용 요금과 LCU(로드 밸런서 용량 단위) 요금의 합계입니다.

- 새 연결 수: 초당 25개를 1 LCU로 판정
- 활성 연결 수: 분당 3,000개의 활성 연결
- 처리된 바이트: 시간당 1GB
- 규칙 평가: 초당 1,000회의 규칙 평가

#### ELB에서 발생하는 오류

- AWS ELB의 기본 최대 연결 시간 제한은 60초
- 60초 동안 데이터를 전달받지 못하면 연결을 자동 종료하고 Timeout 오류를 발생시킴
- 애플리케이션 또는 데이터베이스 계층에서 제한 시간 내 응답하지 못하는 경우가 많음
- 해결 방법: 타임아웃 시간을 늘리거나 애플리케이션에서 서버로 전송하는 데이터 양을 조절

#### 현재 서비스 중인 EC2 인스턴스에 ELB 추가

1. 80번 포트를 외부에서 허용하는 보안 그룹을 생성합니다.
2. 대상 그룹을 생성하고 응답을 수행할 객체를 설정합니다.
3. ALB를 생성하고 보안 그룹과 대상 그룹을 선택합니다.
4. `http://로드밸런서DNS`로 접속해 확인합니다.

503 오류가 발생하면 Target Group을 다시 설정합니다.

### 고가용성 아키텍처 설계

#### 고가용성 (High Availability)

전원 장애, 하드웨어 고장, 네트워크 문제, 자연재해 등 장애 상황에서도 시스템이나 서비스가 중단되지 않고 정상 운영을 지속하는 능력입니다.

- 장애가 발생해도 성능이 떨어지지 않아야 함
- AWS의 ELB는 관리형 서비스이므로 트래픽이 많으면 늘리고 적으면 줄일 수 있음
- AWS에서 고가용성을 구현하려면 다중 가용 영역과 Auto Scaling을 이용
- ELB 생성 시 최소 2개 이상의 가용 영역을 선택하는 것은 고가용성 아키텍처 구현을 위함

#### 가용성 등급

| 가용성 | 예시 |
| --- | --- |
| 99% | 일반적인 블로그나 내부 테스트 환경 |
| 99.9% | 일반적인 엔터프라이즈 서비스의 기본 수준 |
| 99.99% | 고가용성을 달성했다고 보는 표준적인 수준 |
| 99.999% | 금융권, 의료 시스템, 클라우드 핵심 인프라 수준 |

#### 고가용성을 달성하기 위한 3대 핵심 원칙

1. 단일 장애점 제거 (No Single Point of Failure)
2. 이중화 및 다중화
   - 모든 구성 요소를 이중화
   - 구현 방식: Active-Active, Active-Standby
3. 신속한 장애 복구 메커니즘

### 내결함성 (Fault Tolerance)

일부 하드웨어나 소프트웨어에 결함 또는 오류가 발생해도 시스템 전체가 멈추지 않고 기능과 서비스를 계속 유지하려는 능력입니다. 장애 허용 시스템 또는 장애 감내 시스템이라고도 합니다.

#### 내결함성을 구현하는 핵심 기술

- **하드웨어 수준의 예비 부품**
  - RAID(디스크 다중화)
  - Dual Power Supply
- **소프트웨어 및 네트워크 수준의 감지**
  - Replication: 데이터베이스 데이터를 실시간으로 예비 DB에 복사해 두었다가 메인 DB가 중단되면 이어받는 구조
  - 에러 핸들링과 서킷 브레이커: 특정 기능에서 오류가 반복되면 해당 기능으로 가는 길을 잠시 차단하고, 나머지 기능은 정상 작동하도록 격리하는 방식

### 연습 문제

시스템 운영에 `t3.large` 인스턴스 6개가 꼭 필요한 경우, 내결함성과 고가용성을 만족하는 배치는 무엇일까요?

1. 2개의 가용 영역에 각 3대의 인스턴스 배치
2. 3개의 가용 영역에 각 2대의 인스턴스 배치
3. 2개의 가용 영역에 각 6대의 인스턴스 배치
4. 3개의 가용 영역에 각 3대의 인스턴스 배치
5. 1개의 가용 영역에 6대의 인스턴스 배치

- 내결함성: 1, 2, 3, 4
- 고가용성: 3, 4

### Auto Scaling Group을 이용한 고가용성 아키텍처 구현

#### Auto Scaling Group

미리 정의한 조건에 따라 EC2 인스턴스 수를 자동으로 늘리거나 줄이는 인스턴스 관리 그룹입니다.

**필요한 이유**

- 비용 절감: 사용자가 적을 때 서버를 줄이고, 많을 때 서버를 늘려 사용량만큼 비용 지불
- 내결함성 및 고가용성 보장
- 예측하기 어려운 트래픽 대응

**핵심 설정 값**

- 최소 크기
- 최대 크기
- 평상시 원하는 크기

**확장 정책**: 서버를 늘리고 줄이는 규칙

- 대상 추적 확장 정책: 특정 목표 수치를 지정하면 그에 맞춰 자동 조정하는 일반적인 방식
- 단계별 확장 정책: 단계값을 설정해 인스턴스를 추가하거나 줄이는 방식
- 예약된 확장 정책: 이벤트 일정을 알고 있을 때 사용하는 방식
