# Public Cloud

## 2. EC2

### Auto Scaling을 활용한 고가용성 아키텍처 구성

#### Snapshot

- 특정 시점의 디스크 상태를 보존한 백업본
- 디스크의 데이터뿐 아니라 설치된 소프트웨어, 운영체제, 설정 정보도 포함
- EBS 볼륨 단위로 생성하며, 스냅샷을 바탕으로 새 EBS 볼륨을 만들면 원본 볼륨의 복제본이 됨
- 첫 스냅샷은 전체 데이터를 저장하고, 이후 스냅샷은 변경된 데이터만 증분 저장
- AWS 내부적으로 Amazon S3에 저장되지만 사용자가 스냅샷 파일을 직접 다운로드할 수는 없음
- 스냅샷 보관 용량(GB)에 따라 요금이 발생
- Amazon Data Lifecycle Manager(DLM)를 사용하면 스냅샷 생성과 삭제를 자동화할 수 있음
- 스냅샷은 데이터 백업·볼륨 복구에 사용하며, AMI 생성에도 활용됨

#### AMI (Amazon Machine Image)

EC2 인스턴스를 시작할 때 사용하는 이미지 템플릿입니다. 운영체제와 소프트웨어, 인스턴스의 루트 볼륨 구성 등을 포함합니다.

**종류**

- **Quick Start**: AWS가 제공하고 유지 관리하는 기본 이미지
- **My AMIs**: 사용자가 직접 만든 이미지. 같은 환경의 인스턴스를 복제하거나 복구할 때 사용
- **AWS Marketplace**: 소프트웨어가 미리 설치된 이미지. 유료 또는 무료로 제공
- **Community AMIs**: 커뮤니티가 공유한 이미지. 출처와 보안 상태를 확인한 뒤 사용

**사용 목적**

- 동일한 환경의 EC2 인스턴스를 빠르게 복제
- 백업 및 재해 복구
- Auto Scaling에서 새 인스턴스를 시작할 때 기준 이미지로 사용

| 구분 | Snapshot | AMI |
| --- | --- | --- |
| 대상 | EBS 볼륨의 특정 시점 데이터 | EC2 인스턴스를 시작하기 위한 이미지 템플릿 |
| 주요 내용 | 볼륨에 저장된 데이터 | 운영체제와 소프트웨어, 디스크 구성 등 인스턴스 시작에 필요한 정보 |
| 용도 | 볼륨 백업·복구·복제 | 인스턴스 생성·복제·복구 |

**AMI 생성 흐름**: EC2 인스턴스를 선택한 뒤 작업 메뉴에서 이미지 및 템플릿 생성 기능을 사용합니다. 이미지 생성 과정에서 EBS 스냅샷이 만들어질 수 있습니다.

#### 시작 템플릿 (Launch Template)

EC2 인스턴스를 생성할 때 필요한 설정을 저장해 재사용하는 템플릿입니다. Auto Scaling 그룹이 새 인스턴스를 만들 때도 참조합니다.

- AMI와 인스턴스 유형
- 네트워크 및 보안 그룹 설정
- 스토리지 구성
- 키 페어
- 사용자 데이터(User Data)
- 버전 관리와 재사용을 통해 인스턴스 구성을 표준화할 수 있음

#### Auto Scaling 그룹 (ASG)

정의한 조건에 따라 EC2 인스턴스 수를 자동으로 늘리거나 줄이는 그룹입니다. 시작 템플릿을 이용해 인스턴스를 시작하고, 설정한 가용 영역에 분산 배치합니다.

**주요 설정**

- **최소 용량**: 유지할 인스턴스의 최소 수
- **원하는 용량**: 평상시 유지할 인스턴스 수
- **최대 용량**: 확장할 수 있는 인스턴스의 상한
- 여러 가용 영역에 배치하고 로드 밸런서 대상 그룹과 연결하면 장애 대응과 트래픽 분산에 도움이 됨

**확장 정책**

- **동적 크기 조정 정책**: CloudWatch 지표 등을 기준으로 트래픽 변화에 따라 조정
  - 대상 추적: CPU 사용률처럼 목표 지표를 정해 유지
  - 단계별 조정: 지표 구간에 따라 인스턴스 수를 단계적으로 변경
- **예약된 작업**: 사용량이 늘어나는 시각을 알고 있을 때 미리 용량 조정
- **예측 크기 조정**: 과거 사용량의 반복 패턴을 바탕으로 수요를 예측해 사전 조정

**한계와 운영 시 고려 사항**

- 인스턴스 시작과 애플리케이션 준비에는 시간이 걸림
- 트래픽이 급격히 폭증하면 Auto Scaling이 인스턴스를 준비하는 속도보다 요청이 빠르게 늘어 먼저 장애가 발생할 수 있음
- 갑작스러운 트래픽 증가가 예상되면 예약된 작업이나 사전 용량 확보를 함께 고려

#### 리소스 정리

실습 리소스는 의존 관계를 고려해 정리합니다. Auto Scaling 그룹이 관리하는 인스턴스가 남지 않도록 그룹을 먼저 삭제하고, 이후 시작 템플릿·AMI 및 연결된 리소스를 정리합니다.

예시 순서: Auto Scaling 그룹 → 시작 템플릿 → AMI 및 관련 스냅샷 → 로드 밸런서 → 대상 그룹 → 실습용 보안 그룹

### EC2에 MySQL 서버 구성 및 외부 접속

#### MySQL 설치

```bash
sudo apt update
sudo apt install mysql-server
mysql --version
```

#### root 비밀번호 설정

```bash
sudo mysql -u root
```

MySQL 프롬프트에서 인증 방식을 변경하고 권한을 반영합니다.

```sql
ALTER USER 'root'@'localhost'
  IDENTIFIED WITH mysql_native_password BY '<비밀번호>';
FLUSH PRIVILEGES;
```

필요한 경우 이후 접속은 다음과 같이 수행합니다.

```bash
mysql -u root -p
```

#### 외부 접속 설정

MySQL 설정 파일 `/etc/mysql/mysql.conf.d/mysqld.cnf`에서 `bind-address` 값을 외부 인터페이스에서 수신하도록 변경한 뒤 서비스를 재시작합니다.

```bash
sudo nano /etc/mysql/mysql.conf.d/mysqld.cnf
sudo systemctl restart mysql
```

외부 애플리케이션에서 사용할 계정과 데이터베이스를 생성합니다.

```sql
CREATE DATABASE <데이터베이스명>;
CREATE USER '<사용자명>'@'<허용할_호스트>' IDENTIFIED BY '<비밀번호>';
GRANT ALL PRIVILEGES ON <데이터베이스명>.* TO '<사용자명>'@'<허용할_호스트>';
FLUSH PRIVILEGES;
```

- EC2 보안 그룹에서 MySQL 포트 `3306`의 인바운드 규칙을 추가해야 접속 가능
- 실습에서도 접속 원본은 필요한 IP 주소로 제한하고, root 계정의 원격 접속은 피하는 것이 안전함

### EC2에 MongoDB 서버 구성

#### 설치 (Ubuntu 예시)

먼저 배포판 버전을 확인하고, MongoDB 저장소 설정에 맞는 Ubuntu 코드명을 사용합니다.

```bash
cat /etc/lsb-release
sudo apt install -y gnupg curl
curl -fsSL https://pgp.mongodb.com/server-7.0.asc \
  | sudo gpg --dearmor -o /usr/share/keyrings/mongodb-server-7.0.gpg
```

Ubuntu 저장소 목록 파일(`/etc/apt/sources.list.d/mongodb-org-7.0.list`)에 MongoDB 저장소를 추가한 뒤 설치합니다. 아래 `jammy`는 Ubuntu 22.04 예시이므로 실제 운영체제 버전에 맞춰야 합니다.

```text
deb [ arch=amd64,arm64 signed-by=/usr/share/keyrings/mongodb-server-7.0.gpg ] https://repo.mongodb.org/apt/ubuntu jammy/mongodb-org/7.0 multiverse
```

```bash
sudo apt update
sudo apt install -y mongodb-org
sudo systemctl start mongod
sudo systemctl status mongod
mongosh
```

#### 외부 접속 설정

- `/etc/mongod.conf`의 `net.bindIp`를 필요한 네트워크 인터페이스에 맞게 설정하고 MongoDB 서비스를 재시작
- EC2 보안 그룹에서 MongoDB 포트 `27017`을 허용해야 함
- 인터넷 전체에 포트를 개방하지 말고 접속이 필요한 클라이언트의 IP나 애플리케이션 서버 보안 그룹으로 범위를 제한

```bash
sudo nano /etc/mongod.conf
sudo systemctl restart mongod
```

#### 실습 후 정리

패키지를 제거할 때 데이터와 로그 디렉터리를 함께 삭제하면 복구할 수 없습니다. 보존할 데이터가 없는 실습 환경인지 확인한 뒤 정리합니다.

```bash
sudo apt purge 'mongodb-org*'
sudo rm -r /var/log/mongodb
sudo rm -r /var/lib/mongodb
```
