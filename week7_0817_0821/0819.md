### 8) Dockerfile 을 사용하는 이유

- **운영체제 이미지를 이용한 PHP 컨테이너 연동: 대부분 베이스 이미지를 제작할 때 이용**

    - ubuntu 14.04 이미지를 가지고 컨테이너를 생성하는데 바로 접속
        - `docker run --name myweb -p 8000:80 -it ubuntu:14.04`
    - **apache2 설치 및 확인**
        - 도커의 운영체제 이미지는 최소의 것만 가지고 만들어지기 때문에 패키지 정보 업데이트를 가장 먼저 수행
            ```bash
            apt update
            apt install -y apache2
            service apache2 start

            # 다른 터미널에서 실행
            curl localhost:8000
            ```
    - **리눅스 컨테이너 안에서 작업을 수행**
        - 기존 웰컴 파일의 이름을 수정
        - `mv /var/www/html/index.html /var/www/html/index.html.org`
        - 새로운 웰컴 파일을 생성하고 작성
        - `vim /var/www/html/index.html`
            ```html
            <h1>Hello Docker Application</h1>
            ```
    - **PHP 를 설치하고 기본 페이지를 작성해서 확인**
        - `apt install -y php5`
        - 기본 페이지 작성: `vim /var/www/html/index.php`
            ```php
            <?php
             phpinfo();
            ?>
            ```
    - **확인**
        - `curl localhost:8000/index.php`

    - **현재 컨테이너를 이미지로 변경: 다른 터미널에서 수행**
        - `docker commit myweb myphpapp:1.0`
    - 만들어진 이미지를 가지고 컨테이너를 생성해서 실행
        - `docker run -dit -p 8000:80 --name=myphpapp myphpapp:1.0`

- **Dockerfile을 이용해서 위와 동일한 작업을 수행**
    - 디렉토리를 생성하고 그 디렉토리로 이동
        - `mkdir phpweb`
    - Dockerfile 생성
        ```dockerfile
        # 베이스 이미지 설정
        FROM ubuntu:20.04

        # 작성자 정보 - 생략가능
        MAINTAINER "adam <itstudy@kakao.com>"

        #이미지에 대한 설명 - 생략 가능
        LABEL title "IaC PHP Web Application"

        #필요한 패키지 설치
        RUN apt update
        RUN apt install -y tzdata
        RUN apt install -y php
        RUN apt install -y apache2
        RUN apt install -y git
        RUN apt install -y curl
        RUN apt install -y ssh
        RUN apt install -y wget

        #apache 환경변수 설정
        ENV APACHE2_RUN_USER www-data
        ENV APACHE2_RUN_GROUP www-data
        ENV APACHE2_LOG_DIR /var/log/apache2

        #기본 웹페이지를 작성
        RUN echo "Hello Docker Application." > /var/www/html/index.html

        #php 페이지를 작성
        RUN echo "<?php phpinfo(); ?>" > /var/www/html/index.php

        #포트 노출
        EXPOSE 80

        #작업 디렉토리 설정 - RUN, CMD, ENTRYPOINT 명령이 실행되는 디렉토리
        WORKDIR /var/www/html

        #CMD ["/usr/bin/apache2ctl", "-D", "FOREGROUND"]
        CMD ["/usr/sbin/apache2ctl", "-D", "FOREGROUND"]
        ```
    - **Dockerfile 을 이용해서 이미지 생성**
        - `docker build -t 이미지이름 Dockerfile_경로`
        - `docker build -t myphpapp:latest .`
    - **컨테이너로 실행**
        - `docker run -dit -p 8000:80 --name myphpapp myphpapp:latest`
        - 도커 이미지는 잘 생성되었는데 컨테이너 실행이 안되면 CMD가 오류난 것이다. 

### 9) 이미지 빌드 과정

- **Dockerfile 작성 lifecycle**
    - Dockerfile은 인프라 구성을 위해 필요한 명령을 저장한 텍스트 파일
    - docker build 명령을 통해서 작성한 명령을 순서대로 읽으면 자동으로 이미지를 빌드(생성)
    - 빌드는 사용자와의 대화식 처리가 아닌 자동화된 빌드
- **패키지 설치 에러**
    - Dockerfile 작성
        ```dockerfile
        # 오류나는 dockerfile
        FROM ubuntu:20.04

        # apt update 가 없으면 이미지 빌드 시 오류가 남
        RUN apt install python
        ```

    - 이미지 빌드
        - `docker build -t myapp .`
    - 베이스 이미지는 패키지 정보가 업데이트되어 있지 않아서 패키지를 설치할 때는 `apt update`가 선행되어야 한다.

- **자동화되지 않아서 발생하는 에러**
    - Dockerfile 수정
        ```dockerfile
        # 오류나는 dockerfile
        FROM ubuntu:20.04

        RUN apt update
        RUN apt install python
        ```
    - 이미지 빌드
        - `docker build -t myapp .`
    - 에러 발생
        - ERROR: failed to build: failed to solve: process "/bin/sh -c apt install python" did not complete successfully: exit code: 1
    - 패키지 설치 시 자동화시키지 않아서 에러가 발생한 것이므로 수정(최종본)
        ```dockerfile
        # 정상 dockerfile
        FROM ubuntu:20.04

        RUN apt update
        RUN apt install -y python
        ```
    
- Dockerfile 은 새로운 빈 디렉토리에서 생성하여 빌드하는 것을 권장
- 이미지 빌드가 시작되면 현재 디렉토리의 모든 파일과 디렉토리의 내용은 Docker 데몬에 빌드 컨텍스트로 전달되는데 이 때 현재 디렉토리에 있는 파일과 디렉토리 중 제외 대상이 있으면 `.dockerignore` 파일에 기재하면 된다.
- Dockerfile 이 현재 디렉토리나 파일 이름이 다른 경우는 `-f` 옵션을 이용해서 경로를 지정해 주어야 한다.
- docker build는 빌드 속도 향상을 위해서 실행 중간에 있는 이미지 캐시를 이용
    - 첫 번째 빌드 과정에서 단계 별로 캐시를 생성하고 이 빌드 캐시는 동일한 이미지 작업으로 제한
    - 캐시를 적용할 때 순서도 중요하다.
    - 빌드 과정에서 캐시를 사용하지 않으려면 `--no-cache` 를 지정해서 빌드
    - 다른 이미지로부터 만들어진 캐시를 사용해 빌드하려면 `--cache-from` 옵션을 통해 수행
    - 비밀번호 등의 민감한 데이터가 포함되는 경우 secret 구축이 가능

### 10) python django application 을 이미지로 빌드

- **django application 만들기: 가상환경을 만들지 않으면 에러가 발생할 수 있음**
    - 디렉토리 생성
        - `mkdir django_workspace && cd django_workspace`
    - pip 설치
        - `sudo apt install python3-pip`
    - 가상환경 패키지 설치
        - `pip3 install virtualenv --break-system-packages`
    - 가상환경 생성
        - `python3 -m venv ./{가상환경이름}`
    - 가상환경 활성화
        - `source {가상환경이름}/bin/activate`
    - django 패키지 설치
        - `pip install django`
    - 장고 프로젝트 생성
        - `django-admin startproject dockeredjango`
    - 프로젝트 디렉토리로 이동
        - `cd dockeredjango`
    - 실행
        - `python manage.py runserver`
    - 다른 터미널에서 접속해서 `curl localhost:8000` 으로 실행 확인

- **Dockerfile 을 이용한 이미지 생성**
    - 의존성을 텍스트 파일로 내보내기
        - `pip freeze > requirements.txt`
    - **Dockerfile 작성**
        ```dockerfile
        FROM python

        # 패키지 저장소 업데이트하고 불필요한 캐시 삭제
        RUN apt update \
            && apt install -y --no-install-recommends \
            && rm -rf /var/lib/apt/lists/*

        # 작업 디렉토리 설정
        WORKDIR /usr/src/app

        # 패키지 의존성 파일을 복사
        COPY requirements.txt ./

        # 패키지 설치
        RUN pip install -r requirements.txt

        # 디렉토리 모든 파일을 복사 - 소스를 복사
        COPY . .

        # 포트 개방
        EXPOSE 8000

        # 컨테이너로 만들어질 때 수행하는 명령: 장고 프레임워크 실행 명령
        CMD ["python", "manage.py", "runserver", "0.0.0.0:8000"]
        ```

    - **이미지 빌드**
        - docker build -t 이미지이름 -f 도커파일경로 위치
        - `docker build -t dockerdjango:latest .`
    - **컨테이너 생성**
        - `docker run --name dockerdjango -p 8000:8000 -d dockerdjango:latest`

### 11) python fastapi application 을 이미지로 빌드

- **fastapi application을 생성**
    - 디렉토리를 생성하고 이동
        - `mkdir fastapi_workspace && cd fastapi_workspace`

    - 가상환경 생성
        - `python3 -m venv ./myvenv`
    - 가상 환경 활성화
        - `myvenv/bin/active`
    - 패키지 설치
        - `pip install fastapi uvicorn`
    - 코드 작성: `main.py`
        ```py
        from fastapi import FastAPI

        app = FastAPI()

        @app.get("/")
        def read_root():
            return {"Hello":"World"}

        @app.get("/items/{item_id}")
        def read_item(item_id:int, q:str=None):
            return {"item_id":item_id, "q":q}
        ```
    - 실행
        - `uvicorn main:app --reload`
    - 확인
        - `curl localhost:8000`

- **이미지를 만들어서 컨테이너로 실행**
    - 의존성을 텍스트 파일로 내보내기
        - `pip freeze > requirements.txt`
    - Dockerfile 작성
        ```dockerfile
        FROM python

        # 패키지 저장소 업데이트하고 불필요한 캐시 삭제
        RUN apt update \
            && apt install -y --no-install-recommends \
            && rm -rf /var/lib/apt/lists/*

        # 작업 디렉토리 설정
        WORKDIR /app

        # 패키지 의존성 파일을 복사
        COPY requirements.txt ./

        # 패키지 설치
        RUN pip install -r requirements.txt

        # 디렉토리 모든 파일을 복사 - 소스를 복사
        COPY . .

        # 포트 개방
        EXPOSE 8000

        # 컨테이너로 만들어질 때 수행하는 명령: 장고 프레임워크 실행 명령
        CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
        ```
    - .dockerignore 파일 생성 및 작성
        ```dockerfile
        myvenv/
        __pycache__/
        .pytest_cache/
        .env
        ```
    - 이미지 빌드
        - `docker build -t my-fastapi-app .`
    - 컨테이너 생성
        - `docker run -d -p 8000:8000 my-fastapi-app`
    - requirements.txt를 먼저 복사하고 패키지를 설치하는 이유는 도커 때문으로 소스 코드만 수정했을 경우 시간이 오래 걸리는 pip install 단계를 건너뛰도록 하기 위해서

### 13) node 프로젝트를 이미지로 빌드

- node는 실행하는 방법이 python과 유사
- **노드 프로젝트 생성 및 실행**
    - 노드 설치
        - `sudo apt install nodejs npm`
    - 디렉토리를 생성하고 이동
        - `mkdir node_workspace && cd node_workspace`
    - 노드 프로젝트로 변환
        - `npm init`
    - 필요한 패키지 설치
        - `npm install express nodemon`
    - package.json 수정: scripts 부분만 수정
        ```json
        "scripts": {
            "start": "node app.js"
        },
        ```
    - app.js 파일 생성 및 작성
        ```js
        const express = require('express');
        const app = express();
        app.set('port', process.env.PORT || 3000);

        app.get("/", (req, res) => {
                res.send("Hello Express");
        });

        app.listen(app.get('port'), () => {
                console.log(app.get('port'), '번에서 대기중')
        })
        ```
    - 실행
        - `node app.js`
    - 확인
        - `curl localhost:3000`
- **이미지 생성 및 컨테이너 생성**
    - Dockerfile 작성
        ```dockerfile
        FROM node:20-slim

        WORKDIR /usr/src/app

        COPY package*.json ./

        RUN npm install

        COPY . .

        EXPOSE 3000

        CMD ["node", "app.js"]
        ```
    
- **복사되지 않을 내용을 작성: `.dockerignore`**
    ```bash
    node_modules
    npm-debug.log
    .git
    .env
    ```

- **이미지 빌드**
    - `docker build -t node_app .`
- **컨테이너 생성 및 실행**
    - `docker run -d -p 8000:3000 --name nodeapp node_app`

### 14) go 이미지 생성 및 실행

- **go 설치확인**
    - `go version`
- **go 설치**
    - `curl -OL https://golang.org/dl/go1.22.0.linux-amd64.tar.gz`
    - `sudo tar -C /usr/local -xzf go1.22.0.linux-amd64.tar.gz`

- **~/.profile 파일의 PATH에 go 경로를 추가**
    - `echo 'export PATH=$PATH:/usr/local/go/bin' >> ~/.profile`
    - `echo 'export PATH=$PATH:$(go env GOPATH)/bin' >> ~/.profile`
- **적용**
    - `source ~/.profile`
- **go를 이용한 웹 프로그래밍**
    - 디렉토리 생성 후 이동
    - 프로젝트 초기화
        - `go mod init my-go-app`
    - main.go 를 작성

    ```go
    package main

    import (
            "encoding/json"
            "fmt"
            "net/http"
    )

    func main() {
            // 기본 경로 핸들러
            http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
                    w.Header().Set("Content-Type", "application/json")
                    json.NewEncoder(w).Encode(map[string]string{"message": "Hello From Go"})
            })

            http.HandleFunc("/health", func(w http.ResponseWriter, r *http.Request) {
                    fmt.Fprintf(w, "OK")
            })

            fmt.Println("서버가 8000번 포트에서 시작되어서 대기 중")
            if err := http.ListenAndServe(":8000", nil); err != nil {
                    panic(err)
            }
    }
    ```

    - 실행
        - `go run main.go`
    - Dockerfile 작성
        ```dockerfile
        FROM golang:1.23-alpine

        WORKDIR /app

        COPY . .

        # 의존성 다운로드 및 빌드
        RUN go mod download
        RUN go build -o main .

        EXPOSE 8000

        CMD ["./main"]
        ```
    - 이미지 빌드
        - `docker build -t goapp .`
    - 컨테이너 생성
        - `docker run --name goapp -d -p 8000:8000 goapp`

### 15) ADD 명령어의 자동 압축 해제 기능 활용

- 웹 소스 코드 다운로드: `git clone https://github.com/brayanlee/webapp.git`
- 디렉토리 이동: `cd webapp`
- 파일 확인: `ls`
    - `webapp.tar.gz` 파일이 존재
- **Dockerfile 작성**
    ```dockerfile
    FROM ubuntu:latest

    RUN apt update
    RUN apt install -y tzdata
    RUN apt install -y php
    RUN apt install -y apache2

    ADD webapp.tar.gz /var/www/html

    WORKDIR /var/www/html

    EXPOSE 80

    CMD /usr/sbin/apachectl -D FOREGROUND
    ```

- **도커 이미지 빌드**
    - `docker build -t webapp .`
- **컨테이너 생성**
    - `docker run -d -p 8000:80 --name webapp webapp`
