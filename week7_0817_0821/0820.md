### 16) 이미지 용량 절감

- **apt를 이용한 패키지 업데이트와 설치 시 남게 되는 캐시를 제거**
    - 캐시 관련 삭제 명령: apt clean, apt autoremove, rm -rfv
    - 운영체제 베이스 이미지를 사용한 후 apt를 사용한 경우 효과
    - ubuntu base 이미지를 사용하는 웹 서버를 구축(apache2를 설치, /var/www/html 디렉토리에 웰컴 파일을 위치)
        - index.html 파일을 작성
            ```html
            <h1>Hello Docker</h1>
            ```
        - Dockerfile 작성

            ```dockerfile
            FROM ubuntu:latest

            RUN apt update
            RUN apt install -y apache2 -qq --no-install-recommends

            WORKDIR /var/www/html

            ADD index.html .

            EXPOSE 80

            CMD apachectl -D FOREGROUND
            ```

        - 이미지 생성
            - `docker build -t webapp:1.0 .`

        - Dockerfile 수정
            ```dockerfile
            FROM ubuntu:20.04

            RUN apt update
            RUN apt install -y tzdata
            RUN apt install -y php
            RUN apt install -y apache2 

            RUN apt clean -y
            RUN apt autoremove -y
            RUN rm -rfv /var/lib/apt/lists/* /tmp/* /var/tmp/*

            WORKDIR /var/www/html

            ADD index.html .

            EXPOSE 80
            ```
        - 이미지 생성
            - `docker build -t webapp:2.0 .`
    - **작업**
        - `RUN apt clean -y`: 설치에 사용한 패키지 라이브러리, 임시 파일, 오래된 파일을 삭제하는데 autoclean을 사용하면 더 이상 설치되어 있지 않은 패키지들의 .deb까지 삭제
        - `RUN apt autoremove -y`: 다른 패키지들의 종속성을 종속시키기 위해 자동으로 설치된 패키지를 삭제
        - `RUN rm -rfv /var/lib/apt/lists/* /tmp/* /var/tmp/*`: apt와 연관된 캐시 파일을 모두 삭제하는데 이미지의 시스템 소프트웨어를 다시 업데이트할 계획이 있다면 삭제하지 않는 것이 좋음
    - 운영체제에서 많은 패키지를 설치하고 수행하면 디스크 용량이 줄어드는 효과가 있지만, Docker 이미지에서는 레이어가 이미 생성된 뒤 삭제하면 이전 레이어의 용량까지 완전히 줄어들지 않을 수 있다. 따라서 패키지 설치와 캐시 삭제를 하나의 `RUN` 명령에서 연속해서 수행하는 것이 효과적이다.

### 17) 다단계 빌드

- **개요**
    - 빌드 단계를 여러 단계로 나누어 빌드하는 것
    - 각 빌드 단계는 FROM 명령어로 시작하며 필요한 경우 빌드 단계에 AS 파라미터를 이용해서 이름을 붙일 수 있음
    - 빌드가 여러 단계로 구성된 경우 최종 산출물을 마지막 단계의 내용을 담은 도커 이미지
    - 각 빌드 단계는 독립적으로 실행되지만 앞선 단계에서 만들어진 디렉토리나 파일을 복사할 수 있음
    - 멀티 스테이지 Dockerfile 스크립트를 통해 빌드 과정을 세밀하게 조정하면 최종 산출물인 이미지를 가능한 작게 유지할 수 있음

- **node 다단계 빌드**
    - `mkdir node_workspace && cd node_workspace`
    - Dockerfile 생성

        ```dockerfile
        FROM node:20-slim AS builder
        WORKDIR /app
        COPY package.json ./
        RUN npm install
        COPY . .

        FROM node:20-alpine
        WORKDIR /app
        COPY --from=builder /app ./

        EXPOSE 3000
        USER node
        CMD ["node", "app.js"]
        ```
    - 이미지 빌드: `docker build -t nodeapp:2.0`

- **Java Gradle 다단계 빌드**
    - 스프링 부트 애플리케이션 생성
        - `git clone https://github.com/itggangpae/spring_docker.git`
    - Dockerfile 작성

        ```dockerfile
        FROM eclipse-temurin:21-jdk AS build

        WORKDIR /app

        COPY gradlew .
        COPY gradle gradle

        RUN chmod +x gradlew

        COPY build.gradle .
        COPY settings.gradle .

        RUN ./gradlew dependencies --no-daemon

        COPY src src
        RUN ./gradlew clean build -x test --no-daemon


        FROM eclipse-temurin:21-jre
        WORKDIR /app
        COPY --from=build /app/build/libs/*.jar app.jar
        EXPOSE 8080
        ENTRYPOINT ["java", "-jar", "app.jar"]
        ```
    - 변경 내용
        - 이전에는 외부에서 빌드를 한 다음 빌드한 결과를 복사했는데 이번에는 내부에서 빌드를 하고 실행을 할 때는 jdk 대신에 jre를 사용해서 용량을 줄임

    - **Go 언어 다단계 빌드**
        - Dockerfile 작성

            ```dockerfile
            FROM golang:1.23-alpine AS builder

            WORKDIR /app
            COPY go.mod go.sum* ./
            RUN go mod download

            COPY . .
            RUN CGO_ENABLED=0 GOOS=linux go build -o main .

            FROM alpine:latest
            RUN apk --no-cache add ca-certificates
            WORKDIR /root/
            COPY --from=builder /app/main .

            EXPOSE 8000
            CMD ["./main"]
            ```

    - **Python 다단계 빌드**
        - 빌드 단계에서 가상 환경을 만들고 의존성 패키지를 설치한 뒤, 실행 단계에는 가상 환경과 애플리케이션 코드만 복사한다.

            ```dockerfile
            FROM python:3.12-slim AS builder

            WORKDIR /app
            ENV PYTHONDONTWRITEBYTECODE=1 \
                PYTHONUNBUFFERED=1

            RUN python -m venv /opt/venv
            ENV PATH="/opt/venv/bin:$PATH"

            COPY requirements.txt ./
            RUN pip install --no-cache-dir -r requirements.txt

            FROM python:3.12-slim
            WORKDIR /app
            COPY --from=builder /opt/venv /opt/venv

            ENV PATH="/opt/venv/bin:$PATH" \
                PYTHONDONTWRITEBYTECODE=1 \
                PYTHONUNBUFFERED=1

            COPY . .
            RUN adduser --disabled-password --gecos "" appuser
            USER appuser

            EXPOSE 8000
            CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
            ```

        - Python 애플리케이션은 실행에 필요한 패키지만 포함하도록 경량 베이스 이미지(`python:3.12-slim` 등)를 선택하는 것이 좋다.

### 18) Dockerfile 작성 시 유의사항

- **이미지 크기 최소화**
    - 이미지가 무거우면 배포 속도가 느려지고 저장 공간을 많이 차지하므로 가능한 한 작게 만들어야 한다.
    - `alpine`이나 `slim`과 같은 경량 베이스 이미지를 사용한다.
    - Dockerfile 명령어의 수는 이미지 레이어 수와 관련이 있으므로, 불필요하게 많은 레이어를 만들지 않는다.
    - 여러 개의 `RUN` 명령어를 `&&`로 연결하면 하나의 레이어로 만들 수 있다.
    - 빌드에 사용한 패키지 캐시와 불필요한 파일은 삭제한다.

- **빌드 캐시 활용**
    - 도커는 빌드 시 변경되지 않은 레이어를 재사용하므로 이 효율을 극대화
    - 순서가 중요
        - 자주 바뀌는 소스 코드 복사(COPY . .) 는 나중에
        - 잘 바뀌지 않는 의존성 설치는 앞 부분에 배치
    - .dockerignore 작성: git, 로그 파일, 로컬 노드 모듈 등 빌드에 필요없는 파일이 이미지에 포함되지 않도록 설정

- **보안 및 관리 설정**
    - root 계정 사용 지양: 보안을 위해 USER 명령을 사용하여 별도의 일반 사용자 계정으로 프로세스를 실행하는 것이 안전
    - 명확한 태그 사용: latest 태그는 버전 관리가 어려우므로 v1.0.1 처럼 명확한 태그 사용을 권장
    - 멀티 스테이지 빌드를 사용하면 컴파일러와 빌드 도구는 빌드 단계에만 남기고, 최종 이미지에는 실행에 필요한 파일만 포함할 수 있어 보안과 용량을 함께 개선할 수 있다.
- 하나의 애플리케이션은 하나의 컨테이너로
    - 하나의 컨테이너에 2개 이상의 애플리케이션을 설정하게 되면 애플리케이션의 결합성이 높아지게 되고 확장성을 저해
    - 모놀리식 구성보다는 결합 해제된 애플리케이션(decoupling) 설계나 마이크로서비스 지향적 설계를 고려해야 장애가 발생하더라도 애플리케이션 자체가 유지될 수 있음
- IaC 환경 개발은 디렉토리 단위로 수행
    - 이미지를 빌드할 때 지정한 디렉토리의 모든 파일과 하위 디렉토리가 Docker context에 포함된다.
    - 별도의 디렉토리를 만들어서 사용하는 것을 권장
- 서버리스 환경으로 개발
    - Dockerfile 등을 통해 미리 설정된 실행 환경을 만들고, 서버를 직접 배포·확장·관리하지 않아도 애플리케이션을 실행할 수 있는 환경이다.
    - 다양한 애플리케이션과 백엔드 서비스를 고가용성으로 확장하는 데 필요한 작업을 클라우드 서비스가 자동으로 처리한다.

## 9. docker compose

### 1) 개요

- 분산 애플리케이션을 기준으로 보면 Dockerfile 은 애플리케이션의 한 부분을 패키징하는 수단
- Web Frontend, Backend API, Database 를 갖춘 애플리케이션을 패키징하려면 각 컴포넌트에 하나씩 3개의 Dockerfile 파일이 필요하고 순서대로 각각의 컨테이너를 실행해야 하는데 이런 수동 프로세스는 오류를 발생시킬 가능성이 높음
- 공통의 목적을 갖는 애플리케이션 스택을 yaml 코드로 지정해서 한 번에 서비스를 올리고 관리할 수 있는 도구가 `docker compose`
- Docker Compose 파일은 애플리케이션을 구성하는 여러 서비스와 컴포넌트의 원하는 상태를 선언적으로 정의하는 파일이다. 어떤 서비스를 사용할지, 각 서비스의 설정과 네트워크·볼륨을 어떻게 구성할지 기술하며, 정의된 모든 서비스가 정상적으로 실행되었을 때의 애플리케이션 상태를 나타낸다.

- docker compose run 명령으로 컨테이너를 실행할 때 지정하는 모든 옵션을 한데 모아놓은 형식의 파일
- docker compose 파일을 작성하면 docker compose 도구를 사용해서 애플리케이션을 실행
- docker compose가 컨테이너, 네트워크, 볼륨 등 필요한 모든 docker 객체를 만들도록 docker API 에 명령을 내림
- docker compose로 실행된 컨테이너는 독립된 기능을 가지며 공통 네트워크로 구성되기 때문에 컨테이너 간 통신이 쉬움
- docker compose는 테스트, 개발, 운영 등의 모든 환경에서 구성이 가능한 오케스트레이션 도구 중 하나이지만 다양한 관리 기능을 가지고 있지 않기 때문에 테스트와 개발환경에 적합
- 실제 운영 환경은 많은 관리적 요소가 필요하기 때문에 도커 스웜이나 쿠버네티스와 같은 오케스트레이션 도구가 가지고 있는 자동 확장, 모니터링, 복구 등의 운영에 필요한 기능과 함께 사용되는 것을 권장
- up 명령으로 한꺼번에 생성
- down 명령으로 한꺼번에 정지 및 삭제

### 2) 설치

- Windows 나 Mac 에서 Docker Desktop을 설치했으면 설치를 별도로 할 필요가 없음
- **리눅스에서만 별도로 설치**
    - 심볼릭 링크 생성: `sudo ln -s /usr/local/bin/docker-compose /usr/bin/docker-compose`
    - 소유자 변경: `/usr/local/bin/docker-compose`
    - 버전 확인: `docker-compose --version`

### 3) 작성 및 실행

- **apache 웹 서버 컨테이너 생성**
    - `docker run --name apache_1 -d -p 8080:80 httpd`
- **docker compose 이용해서 위와 동일한 작업 수행**
    - docker compose 파일 생성(`docker-compose.yaml`)

        ```yaml
        version: "3"
        services:
            apache_1:
                image: httpd
                ports:
                    - "8081:80"
                restart: always
        ```

    - 실행: `docker compose up -d`

- **Maria DB 컨테이너**
    - 일반적인 컨테이너 생성 명령
        ```dockerfile
        docker run -d --name mariadb-server \
            -p 3306:3306 \
            -e MYSQL_ROOT_PASSWORD=your_password \
            -v ~/mariadb/data:/var/lib/mysql \
            --restart always \
            mariadb:10.4.6
        ```
    
    - docker-compose 활용
        - docker-compose.yaml 파일 작성

            ```yaml
            version: "3.8"

            services:
              mariadb:
                image: mariadb:10.4.6
                container_name: mariadb-server
                restart: always
                ports:
                  - "3307:3306"
                volumes:
                  - ./data:/var/lib/mysql
                environment:
                  MYSQL_ROOT_PASSWORD: your_password
            ```
        - docker-compose 컨테이너 생성: `docker compose up -d`
        - docker compose 로 생성된 내용을 확인: `docker compose ps`
        - docker network ls 명령을 수행해보면 docker compose 가 만든 기본 네트워크를 확인할 수 있다.
        - 동일한 네트워크로 만들어져 있으면 IP 대신에 이름으로 통신이 가능
