## 7) Playbook

### 설정과 함께 nginx 배포

- nginx가 실행되면 보여질 welcome file 작성: `index.html`

```html
<html>
  <head>
    <title>Welcome To Nginx</title>
  </head>
  <body>
    <h1>nginx configured by ansible</h1>
  </body>
</html>
```

- nginx 설정 파일: `nginx.conf`

```nginx
server {
  listen 80 default_server;
  listen [::]:80 default_server ipv6only=on;

  root /usr/share/nginx/html;
  index index.html index.htm;

  server_name localhost;

  location / {
    try_files $uri $uri/ =404;
  }
}
```

- 배포파일: `webservers.yml`

```yaml
- name: Configure WebServer with nginx
  hosts: all
  become: yes  # 관리자 권한으로 명령을 수행
  tasks:
    - name: Install Nginx
      apt:
        name: nginx
        state: present

    - name: Copy nginx config file
      copy:
        src: nginx.conf
        dest: /etc/nginx/sites-available/default

    - name: Manage Configuration
      file: >
        dest=/etc/nginx/sites-enabled/default
        src=/etc/nginx/sites-available/default
        state=link

    - name: Copy Welcome File
      copy:
        src: index.html
        dest: /usr/share/nginx/html/index.html

    - name: Restart Nginx
      service: name=nginx state=restarted
```

- 실행: `ansible-playbook -b -K webservers.yml`
- 확인: `curl 관리노드의IP`

- nginx를 제거하는 배포파일: `remove-nginx.yml`

```yaml
- name: Remove with nginx
  hosts: all
  become: yes  # 관리자 권한으로 명령을 수행
  tasks:
    - name: Stop Nginx Service
      service:
        name: nginx
        state: stopped
      ignore_errors: yes

    - name: Remove Nginx and related packages
      apt:
        name:
          - nginx
          - nginx-common
          - nginx-full
          - nginx-core
        state: absent
        purge: yes
        autoremove: yes

    - name: Reload Systemd daemon
      systemd:
        daemon_reload: yes
```

## 8) Variable & Facts

변수를 잘 활용하면 **플레이북을 재사용**할 수 있으며 사용자로부터 받은 값도 쉽게 적용할 수 있다.

### 변수 종류

- **그룹 변수**
  - 인벤토리에 정의된 호스트 그룹에 적용하는 변수
  - 인벤토리 파일에 특정 그룹의 변수를 선언할 수 있음

`inventory.ini` 파일에 추가:

```ini
[all:vars]
user=ansible
```

`create-user.yml` 파일에서 사용:

```yaml
- hosts: all
  tasks:
    - name: Create User {{ user }}
      ansible.builtin.user:
        name: "{{ user }}"
        state: present
```

실행한 후 관리 노드에서 `ll /home`으로 `ansible`이라는 디렉터리가 생성되었는지 확인한다.

- **호스트 변수**
  - 인벤토리 파일에서 호스트 옆에 선언
  - 해당 호스트에서만 사용 가능

```ini
[itstudy]
192.168.0.201 user=ansible1
192.168.0.202

[all:vars]
user=ansible
```

- **플레이 변수**
  - 플레이북 내에서 선언한 변수

`create-user.yml` 파일 수정:

```yaml
- hosts: all
  vars:
    user: ansible2
  tasks:
    - name: Create User {{ user }}
      ansible.builtin.user:
        name: "{{ user }}"
        state: present
```

- **추가 변수**
  - 외부에서 `ansible-playbook`을 실행할 때 파라미터로 넘겨주는 변수
  - 직접 넘겨주기: `ansible-playbook -e user=ansible3 create-user.yml`
  - 파일을 만든 후 플레이북의 `vars_files:` 항목에 파일 경로를 작성하면 외부 파일로도 변수를 불러올 수 있음

- **작업 변수**
  - 태스크 수행 결과를 저장하는 변수
  - 작업 결과를 후속 작업에서 사용할 때 이용
  - `register` 키워드에 변수 이름을 설정

`create-user.yml` 파일 수정:

```yaml
- hosts: all
  tasks:
    - name: Create User {{ user }}
      ansible.builtin.user:
        name: ansible5
        state: present
      register: result
      become: yes

    - ansible.builtin.debug:
        var: result
```

### Facts

- **Facts**는 Ansible이 관리 호스트에서 자동으로 검색한 변수다.
- 호스트별 정보가 포함되어 있다.
  - 호스트 이름
  - 커널 버전
  - 네트워크 인터페이스 이름
  - 운영체제 버전
  - CPU 개수

모든 팩트 확인:

```yaml
- hosts: all
  tasks:
    - name: Print all facts
      ansible.builtin.debug:
        var: ansible_facts
```

팩트를 가져와서 사용:

```yaml
- hosts: all
  tasks:
    - name: Print facts
      ansible.builtin.debug:
        msg: >
          The default IPv4 address of {{ ansible_facts.fqdn }}
          is {{ ansible_facts.default_ipv4.address }}
```

사용자가 만드는 것도 가능하다.

## 9) 제어문

### 반복문

- **반복문을 사용하지 않는 구조**

```yaml
- hosts: all
  tasks:
    - name: Check sshd state
      ansible.builtin.service:
        name: ssh
        state: started
      become: yes

    - name: Check rsyslog state
      ansible.builtin.service:
        name: rsyslog
        state: started
      become: yes
```

- **반복문 사용**

```yaml
- hosts: all
  tasks:
    - name: Check sshd and rsyslog state
      ansible.builtin.service:
        name: "{{ item }}"
        state: started
      become: yes
      loop:
        - ssh
        - rsyslog
```

- **변수에 저장해서 수행**

```yaml
- hosts: all
  vars:
    services:
      - ssh
      - rsyslog
  tasks:
    - name: Check sshd and rsyslog state
      ansible.builtin.service:
        name: "{{ item }}"
        state: started
      become: yes
      loop: "{{ services }}"
```

### 조건문

- `when`
- 조건문과 Facts 등을 적절히 이용하면 서로 다른 운영체제에 동일한 작업을 수행하는 것도 가능하다.

기본 사용법:

```yaml
- hosts: all
  vars:
    run_my_task: true
  tasks:
    - name: echo message
      ansible.builtin.shell: "echo test"
      when: run_my_task
```

운영체제 확인:

```yaml
- hosts: all
  vars:
    supported_distros:
      - RedHat
      - CentOS
  tasks:
    - name: Print Supported OS
      ansible.builtin.debug:
        msg: "This {{ ansible_facts['distribution'] }} need to use dnf"
      when: ansible_facts['distribution'] in supported_distros
```

`or`나 `and`를 이용해서 여러 개의 조건을 적용하는 것도 가능하다.

```yaml
- hosts: all
  vars:
    supported_distros:
      - RedHat
      - CentOS
  tasks:
    - name: Print Supported OS
      ansible.builtin.debug:
        msg: "This {{ ansible_facts['distribution'] }} {{ ansible_facts['distribution_version'] }}"
      when:
        - ansible_facts['distribution'] == "Ubuntu"
        - ansible_facts['distribution_version'] == "26.04"
```

- **반복문과 조건문 같이 사용**

```yaml
- hosts: all
  tasks:
    - name: Print Root Directory Size
      ansible.builtin.debug:
        msg: "Directory {{ item.mount }} size is {{ item.size_available }}"
      loop: "{{ ansible_facts['mounts'] }}"
      when: item['mount'] == "/"
```

### 이전 작업의 결과를 이용하기

```yaml
- hosts: all
  tasks:
    - name: Get rsyslog service status
      ansible.builtin.command: systemctl is-active rsyslog
      register: result

    - name: Print rsyslog status
      ansible.builtin.debug:
        msg: "Rsyslog status is {{ result.stdout }}"
      when: result.stdout == "active"
```

## 9) 핸들러

작업이 종료된 후 호출하는 코드다.

```yaml
- hosts: all
  tasks:
    - name: restart rsyslog
      ansible.builtin.service:
        name: "rsyslog"
        state: restarted
      become: yes
      notify:
        - print msg

  handlers:
    - name: print msg
      ansible.builtin.debug:
        msg: "rsyslog is restarted"
```

### 작업 실패 무시

- Ansible은 플레이 시 각 작업의 반환 코드를 평가하여 작업의 성공 여부를 판단한다.
- 작업이 실패하면 이후의 모든 작업을 건너뛴다.
- 작업이 실패해도 플레이를 계속 실행하려면 `ignore_errors` 키워드를 사용한다.

에러가 발생해도 다음 작업을 수행하기:

```yaml
- hosts: all
  tasks:
    - name: Install apache3
      ansible.builtin.dnf:
        name: apache3
        state: latest
      ignore_errors: yes

    - name: Print msg
      ansible.builtin.debug:
        msg: "Before task is error"
```

에러가 발생한 경우 핸들러 호출: `force_handlers: yes`로 설정하면 작업이 실패해서 플레이가 중단되어도 알림을 받은 핸들러가 호출된다.

## 10) Role

### 개요

- 플레이북을 재사용하기 위한 개념
- 사용하는 이유
  - 콘텐츠를 그룹화해서 코드를 다른 사용자와 쉽게 공유
  - 웹 서버, 데이터베이스 서버 또는 Git Repository와 같은 시스템 유형의 필수 요소를 정의
  - 대규모 프로젝트를 쉽게 관리
  - 다른 사용자와 동시에 개발 가능
  - 잘 작성한 롤은 Ansible Galaxy를 이용해 공유하거나 다른 개발자가 만든 롤을 가져올 수 있음

### 구조

- 최상위는 롤의 이름
- 하위 구조
  - `defaults`: `main.yml` 파일에는 롤이 사용될 때 덮어쓸 수 있는 롤 변수의 기본값이 포함된다. 우선 순위가 낮아 플레이북에서 변경할 수 있다.
  - `files`: 롤 작업에서 참조하는 정적 파일
  - `handlers`: `main.yml` 파일에는 롤의 핸들러 정의를 포함
  - `tasks`: `main.yml` 파일에는 롤의 작업 정의를 포함
  - `templates`: Jinja2 템플릿 포함
  - `tests`: 롤을 테스트하는 데 사용할 인벤토리와 `test.yml` 플레이북을 포함
  - `vars`: 롤의 변수 값을 정의

- 명령어 확인: `ansible-galaxy role -h`
- 구조 파악 및 롤 생성: `ansible-galaxy role init my-role`

### 롤을 이용해서 플레이북 개발: Apache Web Server 설치

수행할 작업을 `tasks/main.yml` 파일에 작성:

```yaml
- name: Install Service {{ service_title }}
  ansible.builtin.apt:
    name: apache2
    state: latest
    update_cache: yes
  become: yes

- name: copy file
  ansible.builtin.copy:
    src: "{{ src_file_path }}"
    dest: "{{ dest_file_path }}"
  become: yes
  notify:
    - restart service
```

- 화면에 출력될 정적인 파일: `files/index.html`

```text
Hello! Ansible
```

- 기본 변수를 위한 파일: `defaults/main.yml`

```yaml
service_title: "Apache Web Server"
```

- 변경 가능한 변수를 작성: `vars/main.yml`

```yaml
service_name: apache2
src_file_path: ../files/index.html
dest_file_path: /var/www/html
supported_distros:
  - Ubuntu
  - Debian
```

- `my-role`을 실행할 플레이북: `role-example.yml`

```yaml
- hosts: all
  tasks:
    - name: Print Start Play
      ansible.builtin.debug:
        msg: "Lets start role play"

    - name: Install Service By Role
      ansible.builtin.import_role:
        name: my-role
```

### Ansible Galaxy

- 롤을 올려놓는 사이트
- Ansible Galaxy는 검증 작업을 하지 않음
- URL: https://galaxy.ansible.com

Ansible Galaxy를 이용해서 PostgreSQL 설치:

- 검색: `ansible-galaxy role search postgresql --platforms Ubuntu`
- 상세보기: `ansible-galaxy role info buluma.postgres`
- 롤 가져오기: `ansible-galaxy role install -p roles buluma.postgres`
- 설치된 role 확인: `ansible-galaxy role list -p roles`
- 롤 삭제: `ansible-galaxy role remove buluma.postgres`

### Contents Collection

- Ansible이 처음 만들어졌을 때는 사용되는 모듈을 핵심 소프트웨어 패키지의 일부로 포함했다. 모듈 수가 늘어나면서 업스트림 프로젝트에서 모듈을 관리하기 어려워졌다.
- 모든 모듈은 고유한 이름이 필요하고, 모듈 업데이트를 핵심 Ansible 코드 업데이트와 동기화해야 했다.
- Ansible 콘텐츠 컬렉션을 사용하면 핵심 업데이트와 모듈 및 플러그인 업데이트가 분리된다.
- 유연성도 향상된다.

- 명령어 확인: `ansible-galaxy collection -h`
- 현재 설치된 컬렉션 확인: `ansible-galaxy collection list`

## 11) 도커 설치

### 도커 설치를 위한 Playbook

```yaml
- hosts: all
  become: yes
  tasks:
    - name: GPG키 디렉토리 생성
      ansible.builtin.file:
        path: /etc/apt/keyrings
        state: directory
        mode: '0755'

    - name: GPG 키 다운로드
      ansible.builtin.get_url:
        url: https://download.docker.com/linux/ubuntu/gpg
        dest: /etc/apt/keyrings/docker.asc
        mode: '0644'
        force: yes

    - name: 저장소 강제 주입
      ansible.builtin.copy:
        dest: /etc/apt/sources.list.d/docker.list
        content: "deb [arch=amd64 signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu noble stable"
        mode: '0644'

    - name: 패키지 목록을 강제로 업데이트
      ansible.builtin.apt:
        update_cache: yes

    - name: 도커엔진 설치
      ansible.builtin.apt:
        name:
          - docker-ce
          - docker-ce-li
          - containerd.io
        state: present
        update_cache: yes

    - name: 도커 서비스 시작
      ansible.builtin.service:
        name: docker
        state: started
        enabled: yes
```

### 도커 이미지를 컨테이너로 생성: `deploy-docker.yml`

```yaml
- name: 컨테이너 생성
  hosts: all
  become: yes
  vars:
    container_name: my-web-server
    image_name: nginx-latest
    host_port: 8080
    container_port: 80
  tasks:
    - name: 도커 이미지 가져오기
      community.gerneral.docker_image:
        name: "{{ image_name }}"
        source: pull

    - name: 도커 컨테이너 생성 및 실행
      community.gerneral.docker_container:
        name: "{{ container_name }}"
        image: "{{ image_name }}"
        state: started
        restart_policy: always
        published_ports:
          - "{{ host_port }}:{{ container_port}}"
        env:
          MY_ENV_VAR: "hello ansible"
```
