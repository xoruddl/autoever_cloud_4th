# Argo CD

## 1. Argo Rollouts

### 1) 개요

- 블루-그린, 카나리, 미러링, 다크 카나리, 트래픽 분석 등의 고급 배포 기술을 쿠버네티스에 제공하는 컨트롤러
- 트래픽 관리를 위한 Ambassador, Istio, AWS Load Balancer Controller, NGINX, SMI 등의 Kubernetes 프로젝트와 연동됨
- Prometheus, Datadog, New Relic 등과 연동하여 지속적 배포 상태를 모니터링할 수 있음

### 2) 설치

- 네임스페이스 생성 및 컨트롤러 설치

```bash
kubectl create namespace argo-rollouts
kubectl apply -n argo-rollouts -f https://github.com/argoproj/argo-rollouts/releases/latest/download/install.yaml

# 컨트롤러 파드 확인
kubectl get pods -n argo-rollouts
```

- Kubectl 플러그인 설치(Linux)

```bash
curl -LO https://github.com/argoproj/argo-rollouts/releases/latest/download/kubectl-argo-rollouts-linux-amd64
chmod +x ./kubectl-argo-rollouts-linux-amd64
sudo mv ./kubectl-argo-rollouts-linux-amd64 /usr/local/bin/kubectl-argo-rollouts

# 설치 확인
kubectl argo rollouts version
```

> macOS에서는 파일명의 `linux`을 `darwin`으로 변경한다. Homebrew 사용 시 `brew install argoproj/tap/kubectl-argo-rollouts`로 설치할 수 있다.

### 3) Canary Update

- 새로운 버전을 전체 사용자에게 한 번에 배포하지 않고, 일부 사용자 또는 소수의 트래픽에 먼저 적용하여 시스템 안정성과 오류 여부를 검증하는 점진적 배포 전략

#### 설정

파드 배포용 매니페스트 `rollout.yaml`을 작성한다.

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Rollout
metadata:
  name: rollouts-demo
spec:
  replicas: 5
  strategy:
    canary:
      steps:
        - setWeight: 20
        - pause: {}
        - setWeight: 40
        - pause:
            duration: 30s
        - setWeight: 60
        - pause:
            duration: 30s
        - setWeight: 80
        - pause:
            duration: 30s
  revisionHistoryLimit: 2
  selector:
    matchLabels:
      app: rollouts-demo
  template:
    metadata:
      labels:
        app: rollouts-demo
    spec:
      containers:
        - name: rollouts-demo
          image: argoproj/rollouts-demo:blue
          ports:
            - name: http
              containerPort: 8080
              protocol: TCP
```

#### 배포 및 카나리 진행

```bash
# 배포 및 파드 확인
kubectl apply -f rollout.yaml
kubectl get pods

# 새 이미지로 업데이트하여 카나리 배포 시작
kubectl argo rollouts set image rollouts-demo rollouts-demo=argoproj/rollouts-demo:yellow

# Rollout 상태를 실시간 모니터링
kubectl argo rollouts get rollout rollouts-demo --watch

# 일시 정지된 단계를 수동으로 다음 단계로 진행
kubectl argo rollouts promote rollouts-demo
```

- `setWeight`는 새 버전(Canary)의 배포 비율을 설정함
- `pause: {}`는 수동 승인 전까지 무기한 일시 정지함
- `pause.duration`은 지정 시간 후 자동으로 다음 단계로 진행함
- 이미지 업데이트 후 `kubectl get pods`를 실행하면 기존 이미지 파드와 새 이미지 파드가 단계적으로 공존하는 것을 확인할 수 있음

#### GUI 대시보드

```bash
kubectl argo rollouts dashboard
```

- 기본 포트는 `3100`, 기본 경로는 `/rollouts`이므로 대시보드를 실행한 **로컬 환경**에서 `http://localhost:3100/rollouts`로 접속함
- 원격 서버에서 실행한 경우 SSH 포트 포워딩 등을 사용해야 하며, 포트만 개방해 외부에 직접 노출하지 않도록 주의함

# Private Cloud

## 1. Ansible

### 1) DevOps 툴 중에 가장 많이 사용하는 툴

- Kubernetes: docker swarm
- Jenkins: Git Actions, TeamCity
- Git Lab: Git Hub
- Argo CD: Flux
- Terraform: Ansible, Puppet, Progress Chef
- Prometheus: Nagios
- Grafana: Datadog
- Open Stack: Public Cloud
- 로그 관리

### 2) IaC

- 개요
    - 시스템, 하드웨어 또는 인터페이스의 구성 정보를 파일을 통해 관리하고 프로비저닝
    - 버전 관리를 통한 리소스 관리
- 도구
    - Terraform
    - Ansible
    - Puppet
    - Progress Chef

### 3) Terraform과 Ansible 비교

| 구분 | Terraform | Ansible |
| --- | --- | --- |
| 개발 회사 | HashiCorp | Red Hat |
| 주요 사용 용도 | 클라우드 인프라 관리 | 서버 구성 관리, 배포 |
| 도구 종류 | IaC 도구 | IT 자동화 도구 |
| 작업 정의 언어 | HCL | YAML |
| 에이전트 필요성 | 없음 | 없음 |
| 퍼블릭 클라우드 지원 | 거의 모든 퍼블릭 클라우드 지원 | 일부분 지원 |

### 4) Ansible

- 개요
    - 여러 서버를 효율적으로 관리할 수 있도록 파이썬으로 만들어진 환경 구성 자동화 도구
    - IT Infrastructure 자동화 도구
    - 모든 호스트에 대해 병렬로 작업을 수행함
    - 다음 작업으로 넘어가기 전, 모든 호스트에서 해당 작업이 완료될 때까지 대기함
    - 작업은 지정한 순서대로 진행됨
- 장점
    - **Agentless**: SSH로 접속하여 작업을 수행함
    - **Idempotency(멱등성)**: 동일한 연산을 여러 번 적용해도 결과가 달라지지 않는 성질
    - **Simple**: YAML 형식과 Jinja2 템플릿을 사용하며 다양한 플레이북 예제를 제공함
    - Push 기반 서비스
- 수행 가능한 작업
    - 소프트웨어 설치, 파일 및 스크립트 배포, 다운로드, 스크립트 실행
    - 버전 관리, 암호화, 운영체제 관련 명령 실행
    - 인프라 관리(Public Cloud, VMware, OpenStack 등), Container, Build & Test
- 작업 결과
    - `ok`: 변경 없이 정상 완료
    - `failed`: 작업 실패
    - `changed`: 변경 발생
    - `unreachable`: 관리 노드에 연결할 수 없음
- 사용 가능 환경
    - Linux, Unix, macOS에서 사용 가능하며 Windows는 WSL 환경을 지원함
    - Ansible Core를 설치하고 플레이북을 작성·실행하는 **제어 노드(Control Node)** 와 작업이 수행되는 **관리 노드(Managed Node)** 로 구성됨
    - Ansible은 제어 노드에만 설치하며 관리 노드에는 설치하지 않음
- 관련 자료
    - [공식 GitHub](https://github.com/ansible)
    - [공식 문서](https://docs.ansible.com/ansible/latest/index.html)

### 5) 주요 구성 요소

- **Inventory**
    - 제어 노드가 제어하는 관리 노드 목록을 나열한 파일
    - IP 또는 도메인을 나열하며 그룹화할 수 있음
- **모듈(Module)**
    - Ansible은 관리 노드에서 작업할 때 SSH로 연결한 후 Ansible 모듈 규칙(rules) 스크립트를 푸시하여 동작시킴
    - 대부분의 모듈은 원하는 시스템 상태를 설명하는 매개변수를 받으며, 실행 완료 후 제거됨
- **플레이북(Playbook)**
    - 관리 노드에서 수행할 작업을 YAML 문법으로 순서대로 작성한 파일

### 6) Ubuntu에 설치

> Ansible은 제어 노드에 설치한다.

```bash
sudo apt update
sudo add-apt-repository --yes --update ppa:ansible/ansible
sudo apt install -y ansible

# 설치 확인
ansible --version

# 동작 확인
ansible localhost -m ping
```

- 접속 설정
    - 제어 노드와 관리 노드에는 Python이 설치되어 있어야 함
    - 제어 노드에서 관리 노드로 SSH 접속이 가능한지 확인함
- 새 사용자를 생성하여 접속 가능하도록 설정

```bash
# 사용자 생성 및 비밀번호 설정
sudo adduser <사용자명>
sudo passwd <사용자명>

# sudo 권한 설정
sudo chmod u+w /etc/sudoers
sudo vi /etc/sudoers
# <사용자명> ALL=(ALL:ALL) NOPASSWD:ALL 추가

# SSH 재시작
sudo service ssh restart
```

- 비밀번호 없이 접속

```bash
# 접속하려는 컴퓨터에서 키 생성
ssh-keygen

# 공개 키 복사
ssh-copy-id <계정>@<접속할-컴퓨터-IP-또는-도메인>
```

### 7) Inventory 설정

`inventory.ini` 파일을 생성한다.

```ini
[그룹이름]
<IP-또는-호스트명>
```

```bash
# 인벤토리 확인
ansible-inventory -i inventory.ini --list

# 통신 가능 여부 확인
ansible all -i inventory.ini -m ping
```

인벤토리 파일을 매번 입력하지 않도록 `ansible.cfg`를 작성할 수 있다.

```ini
[defaults]
inventory = ./inventory.ini
```

### 8) 기본 명령어

- 실행 옵션
    - `-i`: 적용할 호스트 파일 경로. 생략 시 `/etc/ansible/hosts` 사용
    - `-m`: 사용할 모듈 선택
    - `-k`: SSH 접속 비밀번호 요청
    - `-K`: 권한 상승(sudo) 비밀번호 요청
    - `--list-hosts`: 적용 대상 호스트 목록 확인
- Ansible은 동일한 명령을 여러 번 수행해도 필요한 경우에만 변경함
- [Ansible 모듈 목록](https://docs.ansible.com/ansible/2.9/modules/list_of_all_modules.html)

```bash
# Shell 명령 실행
ansible all -m shell -a "free -h"

# 파일 복사
touch test.txt
ansible all -m copy -a "src=./test.txt dest=/tmp"
```

#### Nginx 설치 및 삭제

```bash
# SSH 접속 계정 확인
ansible all -m shell -a "whoami"

# 설치: Ubuntu 패키지 모듈 apt 사용
ansible all -m apt -a "name=nginx state=present" -b -K

# 삭제: purge는 설정 파일까지, autoremove는 사용하지 않는 의존성까지 삭제
ansible all -m apt -a "name=nginx state=absent purge=yes autoremove=yes" -b -K
```

- `state=present`: 설치, `state=absent`: 삭제
- `-b`: 권한 상승을 사용하며 sudo 명령이 필요한 경우 사용
- `-K`: 접속한 계정의 비밀번호를 요청

### 9) Playbook

- 개요
    - 서버가 가져야 할 상태를 정의한 설계도
    - 여러 단계의 복잡한 작업을 순서대로 기록한 스크립트
    - YAML 형식으로 작성함
    - 동일한 플레이북을 여러 번 실행해도 이미 설정이 완료된 상태라면 시스템을 중복 변경하지 않음
    - 선언적 구조: 설치 절차보다 결과적으로 어떤 상태여야 하는지를 기술함
- 기본 구조
    - **play**: 작업 대상을 정의
    - **task**: 실제로 실행할 구체적인 작업 단위
    - **module**: task가 실행하는 도구
    - **handler**: 특정 조건이 충족되었을 때 실행하는 보조 작업

#### Ping 테스트

`ping-test.yml` 파일을 작성한다.

```yaml
- hosts: all
  tasks:
    - name: ping
      action: ping
```

```bash
ansible-playbook ./ping-test.yml

# 문법 검사
ansible-playbook ./ping-test.yml --syntax-check
```

#### 파일 복사

`filecopy.yml` 파일 예시이다.

```yaml
- name: Ansible Copy Example Local To Remote
  hosts: all
  tasks:
    - name: copying file with playbook
      copy:
        src: ~/nginx.conf
        dest: /tmp
        owner: adam
        mode: '0644'
```

#### 디렉터리 생성 및 파일 다운로드

`file` 모듈은 `path`, `state`, `mode`로 파일·디렉터리를 관리하고, `get_url` 모듈은 `url`, `dest`로 파일을 다운로드한다.

```yaml
- name: Download Tomcat
  hosts: all
  tasks:
    - name: Create a Directory
      file:
        path: ~/tomcat9
        state: directory
        mode: '0755'
    - name: Download Tomcat9
      get_url:
        url: https://archive.apache.org/dist/tomcat/tomcat-9/v9.0.8/bin/apache-tomcat-9.0.8.tar.gz.sha512
        dest: ~/tomcat9
```

#### Nginx 설치

```yaml
- name: nginx
  hosts: all
  become: yes # 관리자 권한으로 명령 수행
  tasks:
    - name: Install Nginx
      apt:
        name: nginx
        state: present
```

- 동작 확인
    - `shell` 모듈: 파이프라인, 리디렉션, 환경 변수 등이 필요한 복잡한 셸 명령에 유용하지만 셸 인젝션에 유의해야 함
    - `command` 모듈: 단순한 시스템 명령을 안전하게 실행하며 셸 기능을 지원하지 않아 보안성이 높음

```bash
ansible all -m shell -a "systemctl status nginx"
ansible all -m command -a "nginx -v"

# 웹 서버 동작 확인
curl <관리-노드-IP>
```

#### Nginx 제거

```yaml
- name: nginx
  hosts: all
  become: yes
  tasks:
    - name: Stop Nginx
      service:
        name: nginx
        state: stopped
      ignore_errors: yes # Nginx가 없어도 다음 작업 진행
    - name: Remove Nginx
      apt:
        name:
          - nginx
          - nginx-common
          - nginx-full
          - nginx-core
        state: absent
        purge: yes # 설정 파일까지 삭제
        autoremove: yes # 사용하지 않는 의존성 패키지도 삭제
    - name: Reload systemd daemon
      systemd:
        daemon_reload: yes
```

```bash
ansible all -m shell -a "systemctl status nginx"
```

#### 설정과 함께 Nginx 배포

Nginx가 실행될 때 표시할 `index.html` 파일을 작성한다.

```html
<html>
  <head>
    <title>Welcome To Nginx</title>
  </head>
  <body>
    <h1>nginx configured by ansible</h1>
  </body>
</html>
```

Nginx 설정 파일 `nginx.conf` 예시이다.

```nginx
server {
  listen 80 default_server;
  listen [::]:80 default_server ipv6only=on;

  root /usr/share/nginx/html;
  index index.html index.htm;

  server_name localhost;

  location / {
    try_files $uri $uri/ =404;
  }
}
```

배포 파일 `webservers.yml`을 작성한다.

```yaml
- name: Configure WebServer with nginx
  hosts: all
  become: yes
  tasks:
    - name: Install Nginx
      apt:
        name: nginx
        state: present

    - name: Copy nginx config file
      copy:
        src: nginx.conf
        dest: /etc/nginx/sites-available/default

    - name: Manage Configuration
      file:
        dest: /etc/nginx/sites-enabled/default
        src: /etc/nginx/sites-available/default
        state: link

    - name: Copy Welcome File
      copy:
        src: index.html
        dest: /usr/share/nginx/html/index.html

    - name: Restart Nginx
      service:
        name: nginx
        state: restarted
```
